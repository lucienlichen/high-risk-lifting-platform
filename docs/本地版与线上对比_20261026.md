# 本地铜陵版与线上原型对比（2026-10-26）

对比对象：

- 线上：`https://lifting.qiaojiang.cloud/`，依据同日只读走查（`线上原型走查_20261026.md`）和附带截图。本文不改线上环境。
- 本地：`origin/main` 加上铜陵未提交改动（本分支第一笔提交）。这一节不把后面新做的「设备概览」算进两边的差距。

## 结论

两边是同一套冶金台账、同一套「服务总览 → 设备列表 → 单台详情」骨架，六项核心服务的页面都能对上。差距主要在外壳和菜单，不在设备主数据。

线上标题仍是「高风险起重装备智能运维与事故防控云服务平台」，本地改成「设备智能检测监测云服务系统」。线上把安全类入口写成「安全监控」，本地菜单仍叫「远程监测服务」，另外多了数据采集和一组平台服务，少了「故障排查」。两边都没有按二级单位铺开的首页，也都没有厂区平面图或 Unity 模型。演示状态都偏红，安全监控几乎台台报警，不能直接当首页。

所以：业务页面大约差一块菜单和若干文案，交互结构几乎相同；离会议要的「一屏看一个车间」都还差一整页。

## 菜单与路由

两边路由相同：`/login`，`/` 进 `/services`，`/scene/:id`，`/device/:id`。服务不进 URL，靠前端状态。没有独立告警页、地图页或概览页。

| | 线上（走查） | 本地铜陵版 |
|---|---|---|
| 顶栏 | 标题、时钟、搜索、铃铛、admin，只能退出 | 同样结构，标题已改 |
| 登录后 | 直接是服务总览，只有 admin | 有登录页。`group_admin` / `company_admin` / `factory_admin` 会写成三种角色，并收窄服务树 |
| 场景 | 冶金、港口、造船、建筑 | 相同四个场景 |
| 服务分组 | 4 组 15 张卡片 | 5 组。多「数据采集与存储」和「分析与平台服务」（专题分析、报表、培训、系统管理） |
| 安全入口名称 | 安全监控 | 远程监测服务。详情里仍按安全监控 / 健康监测拆开 |
| 维护维修 | 维修、故障排查、基础数据、供给 | 维修、基础数据、供给。菜单里没有故障排查 |
| 知识 | 法律法规、常用标准、检验检测 | 有，名称改成「知识智能服务」 |

本地角色只影响服务菜单左侧树能看见哪些设备，不改变六项服务的算法。线上走查没有角色区分。

## 页面有无

两边都有、且能对上截图的页面：

- 服务总览（左侧单位树 + 右侧服务卡片）
- 场景设备列表，含安全监控、健康监测、健康评估、裂纹预测、故障诊断、风险定量评估
- 设备详情：安全监控工作循环与 GB/T 28264 参数、健康监测分类、结构健康评估、裂纹预测、故障诊断三页签、风险 15 项矩阵

两边都没有：

- 设备概览首页
- 厂区平面图、地图、大屏
- Unity / 应力云图
- 独立告警列表

线上点巡检、部分风险和检验弹窗写着「演示版暂不展示」。本地这些服务有列表或面板，但仍是确定性假数据。制动器抓拍、柔性涡流在两边都是占位。

## 场景与单位树

线上走查的台账，和本地第一步导入后的 `demoDeviceRecords` 一致：

| 场景 | 台数 | 结构 |
|---|---:|---|
| 冶金 | 1979 | 本钢集团 1614 = 板材 883 + 北营 493 + 矿业 238；江苏永钢 365 |
| 港口 | 1097 | 青岛港 712，连云港 385 |
| 造船 | 125 | 招商局金陵船舶 |
| 建筑 | 500 | 中国建筑（本地按分配表生成，不在表格台账里） |

没有荣钢，也没有沙钢。本钢是「集团 → 板块 → 厂」三级。永钢是「集团 → 约一百个分厂/车间/跨」两级。线上走查仍看到永钢重名（「PC构件堆场 / PC构建堆场」）。本地 `normalizeYonggangLocationUnit` 会把「PC构建」收成「PC构件」，并按厂、车间前缀归并，所以树上的名字会比线上少一批重名，但归并规则是前缀截断，仍有「三炼钢加」这类不完整名称。

会议要求的冶金范围（只留本钢板材，加上永钢和沙钢）在这一步的本地版里还没有做。那是后续概览数据改动，不记在这次差距里。

## 演示数据

设备身份（编号、名称、使用地点、本钢/永钢/港口/造船台账）两边对得上。截图里的 `T20080910`、1#炉炉顶，就是本地台账第一条。

状态不是实测，是种子随机数。线上走查看到的现象，本地代码能复现出同样的偏差：

- 安全监控几乎全部「异常 / 报警」，报警次数成串出现
- 健康监测的异常比较稀
- 健康评估里金属结构和电控几乎全异常
- 裂纹萌生时间挤在几个月到一年
- 故障诊断大量同一套文案
- 风险详情能出现 18 分、低风险；线上列表「多为 18」，本地代码是 15 项等级相加，分数会散开，并不锁死在 18

本地把「使用场所」四个选项改成了生产区域口径（普通 / 重点 / 人员密集 / 重大危险）。线上截图仍是「其它、建筑工地、公共场所、学校医院文物保护区」。

## 六项服务

| 服务 | 线上 | 本地铜陵版 |
|---|---|---|
| 安全监控 | 列表：作业状态、监控系统状态、预警状态、报警时间、报警次数。详情有工作循环和 8 个状态开关 | 菜单名是远程监测。列表列和详情参数监控都在，电控与健康监测已拆开 |
| 健康监测 | 金属结构、电控、减速机、制动器、车轮；异常稀疏。详情 5 个页签，制动器是空抓拍 | 列表用约 8% 的种子决定某类是否异常。制动器、钢丝绳仍是图像占位 |
| 健康评估 | 健康 / 亚健康 / 异常。金属结构、电控几乎全异常。详情按主梁、支腿、端梁等汇总损伤度 | 同一套损伤度公式和 0.70 / 0.85 分档，所以结构状态容易全红 |
| 裂纹预测 | 最短萌生寿命，大约 9 个月为红、11–12 个月为橙 | 寿命由损伤度反推。页面上的红橙色标在损伤度 0.85 / 0.70 上，不是按月数着色 |
| 故障诊断 | 减速机、制动器、车轮；健康 / 亚健康 / 高风险。模式很齐 | 列表取监测点状态的最坏值。制动器详情另用一套随机评级，和列表不是同一条规则 |
| 风险定量评估 | 15 项 × 1–4 级，综合分，低风险。列表按分排名 | 指标骨架相同，等级随机相加。分段是 ≤25 / ≤35 / ≤45 / 以上，对应低、一般、较大、重大。列表本身不标黄红 |

## 差距简表

| 差距 | 程度 |
|---|---|
| 路由和「选服务再进列表」的主路径 | 基本一致 |
| 四场景台数和本钢 / 永钢树 | 第一步本地版与线上一致 |
| 六项服务的详情骨架 | 一致，文案和假数据规则有小差异 |
| 平台标题、安全监控的菜单名 | 已分开 |
| 故障排查、数据采集、平台类服务 | 菜单互相多一块、少一块 |
| 使用场所的风险选项、风险分是否锁在 18 | 数据口径已分开 |
| 角色 | 本地有雏形，线上没有 |
| 设备概览、平面图、应力云图 | 两边都没有 |
| 沙钢 783 台、去掉北营和矿业 | 两边都还没有 |

一句话：看单台设备的六个服务，本地铜陵版和线上原型可以当成同一代演示；看首页要不要改成「一个车间一张图」，两边都还停在旧入口上，这段距离比菜单改名大得多。
