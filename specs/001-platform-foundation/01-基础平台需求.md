# 01 基础平台需求

## 1. 租户管理（SPEC-TEN-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| TEN-FR-001 | P0 | 平台应支持创建、编辑、启用和停用租户，维护名称、编码、联系人、状态和有效期。 |
| TEN-FR-002 | P0 | 租户成员以及租户内组织、人员、位置、设备、文件、配置、业务记录、AI 会话和审计记录都必须归属明确租户。 |
| TEN-FR-003 | P0 | 租户管理员只能管理本租户资源；租户间数据在查询、缓存、文件、检索索引和导出中均须隔离。 |
| TEN-FR-004 | P0 | 租户停用后不得继续产生普通业务操作，历史业务和审计记录仍须保留。 |
| TEN-FR-005 | P1 | 支持按租户设置用户数、设备数、文件空间、API 和 AI 使用额度。 |
| TEN-FR-006 | P0 | 简单多租户首期一个普通账户最多有一个有效租户成员关系，不提供普通用户跨租户切换。 |
| TEN-FR-007 | P0 | 创建租户时生成唯一租户编码、根组织和首个租户管理员，并记录初始化结果。 |
| TEN-FR-008 | P0 | 已产生用户或业务数据的租户不得硬删除，停用、归档和合规删除分别控制。 |
| TEN-FR-009 | P0 | 平台管理员默认只管理租户元数据和应用授权，不天然拥有租户业务数据查看权。 |
| TEN-FR-010 | P0 | 首期不支持父子租户、租户间资源共享、租户自助注册、计费和每租户独立身份源。 |
| TEN-FR-011 | P0 | 对象明确区分 `PLATFORM` 与 `TENANT` 作用域；平台运营账户、应用目录、平台模板/字典/配置及其审计可属于平台作用域，租户对象必须有 tenantId，二者不得以空 tenantId 模糊混用。 |

## 2. 组织与人员（SPEC-ORG-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| ORG-FR-001 | P0 | 支持集团、公司、部门、班组等管理关系的多级组织树，不固定层数；厂区只有在确属管理单位时才作为组织。 |
| ORG-FR-002 | P0 | 支持新增、移动、合并、停用组织节点，并保留组织关系调整历史。 |
| ORG-FR-003 | P0 | 人员档案可在没有登录账户时独立存在，并可作为设备责任人、工单执行人、检验人员等业务参与者。 |
| ORG-FR-004 | P0 | 人员至少维护工号、姓名、主要组织、岗位、状态和必要联系方式；可扩展兼职或项目关系。 |
| ORG-FR-005 | P0 | 设备可分别关联资产归属组织、使用组织、维保组织及一个或多个责任人员。 |
| ORG-FR-006 | P0 | 人员字段须分普通、受限和禁止外发等级，并依据字段权限显示、脱敏或隐藏。 |
| ORG-FR-007 | P0 | 人员调动或停用不应破坏历史业务中的人员和当时组织快照。 |
| ORG-FR-008 | P1 | 支持人员资质证书、适用设备类别、签发机构、有效期及到期提醒。 |
| ORG-FR-009 | P0 | 每个租户拥有独立根组织，组织编码在租户内唯一，组织关系不得跨租户。 |

### 2.1 物理位置与区域（SPEC-LOC-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| LOC-FR-001 | P0 | 支持园区、厂区、车间、作业区、安装点等可配置的物理位置树。 |
| LOC-FR-002 | P0 | 位置维护租户内唯一编码、类型、父级、状态、地址/坐标和变更历史。 |
| LOC-FR-003 | P0 | 设备关联明确安装位置，位置变更保留起止时间，不自动改变设备资产/使用组织。 |
| LOC-FR-004 | P0 | 组织表示管理关系，位置表示物理空间；两个原型中的“集团/单位”和“厂区/区域”不得继续共用一个对象。 |
| LOC-FR-005 | P0 | 数据范围可以按位置及下级授权，也可与组织、本人负责和指定设备范围组合。 |
| LOC-FR-006 | P0 | 删除或停用仍有关联设备的位置前必须阻止或完成受控迁移。 |

## 3. 用户、认证与会话（SPEC-USR-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| USR-FR-001 | P0 | 登录账户、租户成员关系与人员档案分开管理并可关联；角色和数据范围绑定租户成员，而非仅绑定全局账户。 |
| USR-FR-002 | P0 | 支持创建/邀请、启用、锁定、解锁、停用账户，并查看账户状态和最近登录信息。 |
| USR-FR-003 | P0 | 账户停用、租户停用或关键权限撤销后，后续受保护请求须按最新状态拒绝。 |
| USR-FR-004 | P0 | 支持安全的密码策略、失败锁定、密码重置和会话失效；认证凭据不得明文存储或进入日志/AI。 |
| USR-FR-005 | P0 | 用户可查看并修改被允许自行维护的个人资料、通知偏好和安全设置。 |
| USR-FR-006 | P0 | 同一租户内登录标识须唯一；批量导入须逐项反馈成功、失败和重复原因。 |
| USR-FR-007 | P1 | 支持单点登录、MFA、临时账户和账户有效期，具体首期方式待确认。 |
| USR-FR-008 | P1 | 用户可查看自己的活跃会话并撤销其他会话。 |
| USR-FR-009 | P0 | 用户名只需在租户内唯一，登录由租户编码/入口与用户名共同确定租户成员。 |
| USR-FR-010 | P0 | 两个业务应用不得维护本地密码、用户或角色权威副本；管理入口统一进入共享底座。 |
| USR-FR-011 | P1 | 当前不迁移两个原型数据；未来如启动外部数据导入，用户、人员和设备须保存来源系统及原标识映射，用于去重和历史追溯。 |

## 4. 角色、权限与数据范围（SPEC-IAM-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| IAM-FR-001 | P0 | 支持平台预置角色和租户自定义角色；原型中的超级管理员、集团管理员、分厂管理员仅作为示例，不作为固定三级权限模型。 |
| IAM-FR-002 | P0 | 权限至少区分查看、新增、修改、删除、导入、导出、提交、审批、执行和控制等动作。 |
| IAM-FR-003 | P0 | 数据范围至少支持本租户、指定组织及下级、本组织、本人负责、本人参与和指定设备集合。 |
| IAM-FR-004 | P0 | 用户可拥有多个角色；权限合并、显式拒绝、临时授权和冲突处理规则必须确定且可解释。 |
| IAM-FR-005 | P0 | 支持设备、结构节点、人员、文件、审计和敏感字段等资源授权。 |
| IAM-FR-006 | P0 | 菜单可见性不能代替接口授权，所有入口均须在服务端重新鉴权。 |
| IAM-FR-007 | P0 | 用户权限变化后，后续页面、API、下载、检索缓存和 AI 工具调用均按最新权限执行。 |
| IAM-FR-008 | P0 | AI 助手使用实际发起用户的权限和数据范围，任何模型或服务账号不得扩大权限。 |
| IAM-FR-009 | P1 | 支持有起止时间的临时授权，以及高权限授予的申请、审批和回收。 |
| IAM-FR-010 | P1 | 授权管理员可查询“某用户为何可见/不可见某资源”的权限解释，但最终权限由确定性规则判断。 |
| IAM-FR-011 | P0 | 资产归属、使用、维保等组织关系本身不自动授予全部权限；平台须配置“关系 × 查看/编辑主档/接入/运行/维修/控制”等动作矩阵及冲突优先级。 |
| IAM-FR-012 | P0 | 权限项使用应用命名空间并标明属于平台、共享底座、数据处理应用或智能运维应用。 |
| IAM-FR-013 | P0 | 租户必须已获应用授权，租户成员角色才可包含该应用权限。 |
| IAM-FR-014 | P0 | 首期数据范围支持本租户、组织及下级、位置及下级、本人负责/参与和指定设备集合。 |
| IAM-FR-015 | P0 | 有效访问由租户、成员状态、应用授权、角色动作、数据范围、字段策略和业务状态共同决定。 |
| IAM-FR-016 | P0 | 租户管理员不能创建平台管理员，也不能授予租户未开通应用或自己无权管理的权限。 |
| IAM-FR-017 | P0 | 各应用注册版本化权限目录；停用权限编码不得被复用为不同含义。 |

## 5. 菜单、字典与平台配置

### 5.1 菜单与入口（SPEC-NAV-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| NAV-FR-001 | P0 | 支持配置多级菜单、排序、图标、路由、状态和所需权限。 |
| NAV-FR-002 | P0 | 菜单和操作入口根据当前租户、角色、数据上下文及功能启停动态展示。 |
| NAV-FR-003 | P0 | 停用入口不应删除历史业务数据；有独立权限的用户仍可从合规入口查看历史。 |
| NAV-FR-004 | P1 | 租户可在平台授权范围内调整名称、排序、可见性和常用功能。 |

### 5.2 数据字典（SPEC-DIC-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DIC-FR-001 | P0 | 支持维护字典类型及其编码、名称、排序、状态、说明和适用范围。 |
| DIC-FR-002 | P0 | 区分平台字典和租户字典；租户修改不得影响其他租户。 |
| DIC-FR-003 | P0 | 已被引用的字典项不得硬删除；停用项不用于新数据，但历史记录仍可解释。 |
| DIC-FR-004 | P1 | 支持导入、导出、版本和变更历史。 |

### 5.3 平台配置（SPEC-CFG-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| CFG-FR-001 | P0 | 支持平台级、租户级和必要的设备级配置，并明确继承及覆盖关系。 |
| CFG-FR-002 | P0 | 配置项须定义用途、类型、默认值、校验规则、敏感等级和生效范围。 |
| CFG-FR-003 | P0 | 无效值不得生效；敏感配置不得向无权用户或 AI 显示完整值。 |
| CFG-FR-004 | P0 | 配置变更须记录发起人、来源、前后值、版本、时间和生效结果。 |
| CFG-FR-005 | P1 | 支持变更预览、审批、定时生效和恢复至上一有效版本。 |

## 6. 文件与业务资源（SPEC-FIL-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| FIL-FR-001 | P0 | 支持文件上传、查看、受控下载、更新、停用和版本历史。 |
| FIL-FR-002 | P0 | 文件至少记录名称、类型、大小、校验值、上传人、上传时间、版本、分类、密级和说明。 |
| FIL-FR-003 | P0 | 文件和图片可关联设备、结构节点、可更换部件、人员、工单、告警、巡检、检验、维修和知识条目。 |
| FIL-FR-004 | P0 | 同一文件可关联多个对象；解除一个关联不应自动删除文件或其他关联。 |
| FIL-FR-005 | P0 | 文件访问须同时校验租户、文件权限和关联业务对象权限，不能仅依赖不可猜测地址。 |
| FIL-FR-006 | P0 | 被业务引用或受保留策略约束的文件不得直接永久删除。 |
| FIL-FR-007 | P0 | 上传内容须进行类型、大小、恶意内容和元数据校验；不可信内容不得成为 AI 指令。 |
| FIL-FR-008 | P1 | 支持在线预览、标签、OCR/全文检索、到期提醒和受控分享。 |
| FIL-FR-009 | P0 | 文件拥有独立密级和 ACL；增加业务关联不得自动扩大访问。访问须同时满足文件策略和本次入口对象权限，跨不同数据范围复用文件须显式共享授权或拆分资源。 |
| FIL-FR-010 | P0 | 区分文件资源、不可变文件版本和底层内容对象（Blob）；业务关联引用明确文件版本，更新文件不得静默改变历史业务证据。 |
| FIL-FR-011 | P0 | 内容哈希可用于同租户内安全去重和完整性校验，但跨租户物理去重不得暴露文件存在性、哈希命中或绕过各自密钥、保留和 ACL。 |

### 7.2 统一待办索引与平台计划任务（SPEC-TSK-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| TSK-FR-001 | P0 | 统一展示当前用户跨应用的待办、已办、逾期和我发起事项，并明确来源应用。 |
| TSK-FR-002 | P0 | 底座待办索引至少保存来源应用、来源对象/版本、负责人、优先级、截止时间、镜像状态和受控入口，不复制应用私有业务载荷。 |
| TSK-FR-003 | P0 | 领取、转派、处理、退回、取消和完成等业务动作由来源应用的正式 API 与状态机执行；底座仅路由、展示和同步结果，不成为 ETL 任务或运维工单的第二权威。 |

| TSK-FR-006 | P0 | 来源应用以带 eventId 和对象版本的事件更新待办索引；重复、乱序或同步失败时可幂等处理和重建，用户打开待办时按当前权限再次鉴权。 |

## 8. 审计与日志（SPEC-AUD-01）

### 8.1 审计范围

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AUD-FR-001 | P0 | 记录登录、退出、失败、锁定、认证方式和会话安全事件。 |
| AUD-FR-002 | P0 | 记录重要数据的新增、修改、删除、导入、导出、审批、控制和配置变更。 |
| AUD-FR-003 | P0 | 记录敏感信息查看、文件下载、批量查询、权限关系查询及审计记录访问。 |
| AUD-FR-004 | P0 | 明确区分用户直接操作、AI 代表用户、系统任务和外部接口等来源。 |
| AUD-FR-005 | P0 | AI 产生的每次工具调用和业务操作须同时关联实际发起用户、AI 会话、模型/工具、业务对象及执行结果。 |
| AUD-FR-006 | P0 | 业务对象详情可反查其关键变更的发起用户、操作来源、确认/审批和审计编号。 |
| AUD-FR-007 | P0 | 失败、拒绝、部分成功和状态未知的操作也须留痕。 |
| AUD-FR-008 | P0 | 审计数据采用仅追加或等效防篡改控制；普通用户不得修改或删除。 |
| AUD-FR-009 | P0 | 日志中的密码、密钥、令牌等禁止记录；其他敏感字段按策略脱敏、加密或记录摘要。 |
| AUD-FR-010 | P0 | 支持授权审计人员按时间、用户、设备、对象、来源、风险和结果检索审计记录。 |
| AUD-FR-011 | P1 | 支持审计记录的受控导出、长期归档和异常提醒。 |
| AUD-FR-012 | P0 | 两个业务应用使用统一审计语义，关键事件记录 applicationId，并可在一处按租户、用户、应用和对象检索。 |
| AUD-FR-013 | P0 | 跨应用调用通过 correlationId/causationId 串联入口操作、共享服务、异步任务和最终业务变化。 |
| AUD-FR-014 | P0 | 应用或服务身份不能覆盖实际用户；没有用户的系统任务明确标记系统发起及原始触发来源。 |

### 8.2 通用审计最小字段

每个关键审计事件至少包含：

- 事件编号、跟踪编号、关联/因果编号；
- 事件作用域、actorTenantId、targetTenantId（如平台支持操作）、实际发起用户、用户组织与角色/数据范围快照；
- 来源应用、操作来源及技术执行身份；
- 动作、目标对象类型和编号；
- 权限判定、策略版本和风险等级；
- 受控参数摘要、前后版本及字段变化；
- 确认人、审批人及其时间（如适用）；
- 开始/完成时间、状态、错误码和补偿结果；
- 客户端与必要的安全上下文。

AI 专项字段见 [04-AI助手需求](./04-AI助手需求.md)。

## 9. 外部接口与服务账号（SPEC-INT-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| INT-FR-001 | P0 | 外部系统和内部服务使用独立身份、最小权限及明确的数据范围，不得共用个人账号。 |
| INT-FR-002 | P0 | 接口须具有版本、输入输出约束、认证、授权、限流、幂等和错误约定。 |
| INT-FR-003 | P0 | 外部调用须记录调用方、实际关联用户（如存在）、目标对象、结果和跟踪编号。 |
| INT-FR-004 | P0 | 服务账号执行用户或 AI 发起的操作时，审计必须同时保存技术身份和真实用户身份。 |
| INT-FR-005 | P0 | 禁止在前端、模型提示词、普通日志和业务响应中暴露服务凭据。 |
| INT-FR-006 | P1 | 支持凭据轮换、调用额度、IP/网络策略和异常调用告警。 |
| INT-FR-007 | P0 | 服务身份记录 scopeType、所属租户（租户作用域时）、应用、负责人、用途、权限、状态和有效期，不能交互登录或作为人员/审批人。 |
| INT-FR-008 | P0 | 普通租户服务身份只能访问一个租户；跨租户平台身份须使用独立受控流程并逐次确认目标租户。 |

## 10. 基础平台关键验收

- TEN-AC-001：租户 A 用户修改请求参数也无法访问租户 B 的设备、文件、向量检索结果或 AI 会话。
- ORG-AC-001：没有账户的人员可以被设置为设备责任人或工单执行人，后续开通账户不丢失原关系。
- ORG-AC-002：人员调动后，新业务按新组织授权，历史业务仍显示发生时的人员和组织。
- LOC-AC-001：平台分别建立“集团—公司—部门”等管理组织树和“园区—厂区—车间—作业区”等位置树；设备位置变化不修改人员组织，两个应用按同一位置范围过滤设备。
- USR-AC-001：账户停用后，旧页面和旧 AI 会话不能继续执行受保护操作。
- USR-AC-002：同一用户名可分别存在于租户 A、B，以租户编码登录后只建立对应租户会话。
- IAM-AC-001：用户通过隐藏菜单地址或直接 API 访问未授权功能时仍被拒绝并留痕。
- IAM-AC-002：用户可看设备但无人员敏感字段权限时，责任人联系方式保持脱敏。
- IAM-AC-003：资产组织、使用组织和外部维保组织对同一设备分别获得配置矩阵允许的动作，任一关系都不会自动获得全部权限。
- FIL-AC-001：检验报告可关联到减速机节点；无设备权限者即使获得文件地址也不能下载。
- FIL-AC-002：同一文件需要关联不同权限范围对象时，不会因新增关联让原本无文件权限的用户读取内容。
- NTF-AC-001：告警通知能定位设备和告警；无对象权限时通知不会泄露敏感内容。
- TSK-AC-001：用户从统一待办发起转派时由来源应用完成状态转换；新负责人获得处理权、原负责人失去处理权，待办索引与来源记录最终一致且只保留一个业务权威状态。
- AUD-AC-001：一次 AI 创建记录可从业务对象反查实际用户、AI 会话、工具、确认人和执行结果。
- AUD-AC-002：AI 或普通 API 操作失败时仍有审计记录，并能判断是否产生业务变更。
- INT-AC-001：服务账号执行操作时，审计不会把服务账号误记为业务发起人。
