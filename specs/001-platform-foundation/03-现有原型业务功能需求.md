# 03 现有原型业务功能需求

## 1. 使用说明

本文件以“当前可访问的前端代码”为原型事实基线，旧文档只作历史参考。原型中的模拟数据、固定算法结果和占位按钮不代表后端能力已经存在。

现状标记：

| 标记 | 含义 |
|---|---|
| 可交互 | 当前可从页面入口进入并完成前端交互 |
| 模拟 | 有展示和交互，但数据、算法或业务结果由前端固定/随机生成 |
| 占位 | 只有入口、提示或按钮，没有完整动作结果 |
| 隐藏旧模块 | 代码存在但当前服务目录不可进入 |
| 目标需求 | 本 Spec 要求完整平台最终具备的业务行为 |

目标系统可以重新设计页面路由和组件，但应延续当前确认后的信息结构、工业平台视觉风格和业务功能，不受当前 Vue 模拟实现约束。

## 2. 当前页面事实基线

| 页面 | 当前路由 | 当前能力 | 现状 |
|---|---|---|---|
| 登录 | /login | 场景选择、用户名密码、三类演示角色、会话恢复 | 可交互但仅演示认证 |
| 服务首页 | /services | 场景、组织/设备树、设备分页、14 个服务入口 | 可交互/模拟 |
| 场景服务页 | /scene/:id | 筛选、分页、卡片/列表和服务汇总 | 可交互/模拟 |
| 设备服务页 | /device/:id | 设备概要、监测工作区、设备级服务面板 | 可交互/模拟 |
| 主框架 | — | 标题、时钟、面包屑、服务切换、退出 | 可交互；搜索/通知部分占位 |

原型角色事实：

- 超级管理员可切换四个场景；
- 集团管理员固定在冶金场景和本钢集团；
- 分厂管理员固定在冶金场景、本钢集团/板材板块/炼铁厂；
- 任意非空账号密码都可通过演示登录，只有 company_admin 和 factory_admin 有专门映射，其他账号进入超级管理员分支；
- 组织范围目前只过滤服务首页树，直接访问场景/设备地址仍可绕过。

这些只是原型角色名称和缺陷。目标版使用 00/01 文档中的可配置角色、动作和数据范围，不沿用模拟登录规则。

原型的 online 字段由“运行/待机”等运行状态直接推导，混淆了设备运行与数据连接；目标版必须按 00/02 文档拆分状态。当前结构应力、减速机、制动器等也只是组件内固定分组和模拟点位，不构成物理结构模板、版本、实例树或通用资源关联。

集中占位/停用行为包括：顶部搜索与通知、设备页刷新、多个报告/历史文件/供给资料下载均无真实动作；维修“重新生成”只播放动画；旧版实时告警、处理告警和一键消警整块停用。目标版不能把这些视为已实现能力。

## 3. 业务场景和范围导航（SPEC-BUS-01）

当前四个业务简称及界面名称：

- 冶金（界面：冶金起重装备）；
- 港口（界面：港口起重装备）；
- 建筑工地（界面：建筑起重装备）；
- 船舶制造/造船（界面：造船起重装备）。

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| BUS-FR-001 | P0 | 用户可在有权场景和组织范围内浏览设备；场景、组织和设备数量随权限及筛选条件一致变化。 |
| BUS-FR-002 | P0 | 支持按设备名称/编号、运行状态、设备类别、组织和必要的风险条件筛选、重置和分页。 |
| BUS-FR-003 | P0 | 支持卡片和列表等视图；设备概要至少展示编号、名称、类型、位置、组织、业务状态和数据接入状态。 |
| BUS-FR-004 | P0 | 所有场景级统计、全局列表和设备级面板必须明确作用范围，不得展示与当前租户/组织/设备无关的全局模拟数据。 |
| BUS-FR-005 | P0 | 用户从服务首页选择组织范围时进入场景级服务，选择具体设备时进入设备级服务；切换服务保留合法上下文。 |
| BUS-FR-006 | P0 | 直接访问场景、设备或服务地址时重新验证权限和资源范围。 |
| BUS-FR-007 | P1 | 场景可由管理员配置名称、图标、适用设备类别和可用服务，不固定为四个。 |

原型列表中的八类关联数据入口作为业务分类输入：

1. 日常点巡检；
2. 损伤/故障维修；
3. 安全监控；
4. 健康监测；
5. 风险定量监测；
6. 检验检测；
7. 设备监管基础数据；
8. 设备制造供给数据。

其中原型只有基础数据、维修和部分健康监测内容相对完整，其余入口多为占位。目标版是否保留这组“八类数据入口”需确认，不能仅因按钮存在即视为 P0。

当前视图切换并非所有服务通用：卡片/列表主要用于通用列表及维修、基础数据、供给的场景页，专用服务表固定为列表。主框架服务切换器只在场景页已有活动服务时出现；直接进入设备路由且没有活动服务时默认打开安全监控。上述行为是原型事实，不预设目标版路由结构。

## 5. 安全监控与健康监测（SPEC-MON-01）

### 5.1 工作日期与工作循环

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| MON-FR-001 | P0 | 用户可按工作日期和工作循环查看监测数据，工作循环至少关联起止时间、吊重、单次起升时长和循环序号。 |
| MON-FR-002 | P0 | 选择工作循环后，趋势、统计和事件统一限制在该业务时间窗口。 |
| MON-FR-003 | P0 | 无作业日、没有数据和数据中断须分别显示，不能用模拟曲线填充。 |
| MON-FR-004 | P0 | 工作循环数据须说明来源、计算规则和版本；人工修正须留痕。 |

### 5.2 安全监控

原型当前重点为电控系统：

- 起重量、起重力矩、起升高度/下降深度；
- 大车/小车行程、幅度、偏斜、风速、回转角度；
- 操作指令、班次时间、累计小时和循环；
- 制动、防风防滑、门限位、机构联锁、安全信号、电缆卷筒和超速保护等状态。

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| MON-FR-010 | P0 | 按设备类别和接入配置展示实际可用的安全监控指标、状态、最新值和趋势。 |
| MON-FR-011 | P0 | 当前值必须附带时间、单位、质量和新鲜度；无实时接入或无点位时显示不适用/未接入。 |
| MON-FR-012 | P0 | 支持异常/告警下钻到设备结构节点、点位、触发条件和处置记录。 |
| MON-FR-013 | P0 | “安全监控”不等同远程控制；如未来提供设备命令，须作为独立高风险能力审批。 |

### 5.3 健康监测

原型当前有以下类别：

1. 结构应力：实测点、孪生推演点、位置图和趋势；
2. 结构损伤：声发射监测，柔性涡流仍为接入占位；
3. 减速机：温度、声音和振动；
4. 制动器：逐小时图片占位；
5. 行走车轮：温度、声音和振动。

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| MON-FR-020 | P0 | 监测分类来自设备结构和接入配置，页面仅展示该设备实际存在且用户有权查看的分类。 |
| MON-FR-021 | P0 | 监测点必须关联结构节点，并支持当前位置、当前值、历史趋势、告警和关联资料。 |
| MON-FR-022 | P0 | 实测值、孪生/模型计算值和人工录入值须明确区分来源，不得混为同一事实。 |
| MON-FR-023 | P0 | 图片型监测保存采集时间、结构节点、来源、识别版本和识别结果；原文件按权限访问。 |
| MON-FR-024 | P0 | 部分接入时显示覆盖率和未覆盖结构，不得给出“整机全部正常”的误导结论。 |
| MON-FR-025 | P1 | 钢丝绳和“其他”是否作为正式监测类别待确认；原型当前并无可达页面。 |

## 10. 隐患排查与问题处理（待确认）

代码中存在但当前 14 项服务目录无法进入：

- 隐患排查：重大/一般隐患、空白模板预览，上传/保存/下载按钮为占位，历史记录和整改建议为模拟；
- 问题处理：设备、人员、环境隐患源及原因、可能事件。

建议目标版不要维持两个相互模糊的孤立抽屉，而是确认是否形成统一闭环：

~~~mermaid
flowchart LR
    S["告警 / 巡检 / 检验 / 诊断 / 人工发现"] --> H["问题或隐患登记"]
    H --> R["风险分级与责任分派"]
    R --> W["整改 / 维修 / 工单"]
    W --> V["复查验证"]
    V --> C["关闭与归档"]
~~~

不论是否恢复两个独立入口，告警、巡检、检验、诊断和 AI 均依赖一套 P0 的统一问题/工单闭环：

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| WRK-FR-001 | P0 | 问题/工单记录至少包含来源、设备/结构节点、分类、等级、证据、责任组织/人员、期限、措施和状态。 |
| WRK-FR-002 | P0 | 支持草稿、待分派、处理中、待复查、已关闭、已退回/重开、已取消等可配置状态及确定性转换权限。 |
| WRK-FR-003 | P0 | 支持分派、转派、接收、处理、提交复查、通过/退回和关闭，每次动作记录用户、时间、意见和附件。 |
| WRK-FR-004 | P0 | 保留从告警/巡检/检验/诊断/人工/AI 到问题、维修工单、复查和关闭的来源链，并避免重复创建。 |
| WRK-FR-005 | P0 | AI 可在权限内查询或生成草稿、提出分派/提交等操作，但执行正式状态转换须使用同一业务 API、确认和审计。 |

是否将“隐患”作为具有重大/一般等法定分类的专门对象、是否恢复“隐患排查/问题处理”两个入口，仍由 DEC-013/017 确认。

## 11. 页面与交互连续性（SPEC-UX-01）

| 编号 | 优先级 | 目标需求 |
|---|---:|---|
| UX-FR-001 | P0 | 延续当前深蓝工业平台风格、信息密度和场景/组织/设备/服务的操作心智，但不要求复用现有代码。 |
| UX-FR-002 | P0 | 页面必须清楚区分业务运行状态、实时接入状态、风险/健康状态，避免只用一个颜色或“在线”表达。 |
| UX-FR-003 | P0 | 模拟、计算、实测、人工和 AI 结果在视觉及文本上可辨识。 |
| UX-FR-004 | P0 | 所有上传、下载、刷新、搜索、通知和 AI 生成按钮在交付版本中必须有真实行为或明确禁用说明，不能保留误导性占位。 |
| UX-FR-005 | P0 | 表格、图表和卡片均显示数据范围、统计时间和更新时间；无数据不生成伪造曲线。 |
| UX-FR-006 | P0 | 用户在无权限、无接入、无数据、数据延迟、部分失败时得到不同且可行动的反馈。 |

## 12. 业务关键验收

- BUS-AC-001：集团/厂区用户只能查看授权组织设备，直接输入其他场景或设备地址仍被拒绝。
- BUS-AC-002：选择组织后设备数量、服务统计和明细使用相同范围；选择设备后只显示该设备数据。
- MON-AC-001：安全监控仅展示已配置指标，未接入设备显示未接入而非模拟实时数据。
- MON-AC-002：切换工作日期和循环后，所有趋势统一使用该时间窗口并说明是否缺数。
- MON-AC-003：健康监测能从测点下钻到结构节点，部分接入时明确覆盖范围。
- INS-AC-001：巡检文本先生成结构化草稿，用户确认后形成正式记录并能追溯原文。
- INS-AC-002：检验到期规则产生预警和待办，报告可以按权限真实预览/下载。
- DIA-AC-001：健康、裂纹、故障和风险结果均展示算法/规则版本、输入时间、数据质量和证据。
- DIA-AC-002：数据过期或覆盖不足时，不输出无条件的整机正常结论。
- MNT-AC-001：诊断建议经用户确认形成维修工单，并从工单反查诊断来源。
- MNT-AC-002：基础数据和供给记录均关联权威设备主档，不出现与当前范围无关的独立随机数据。
- WRK-AC-001：告警形成问题/工单后可完成分派、处理、复查、退回/重开和关闭，所有状态转换及来源可追溯。
- WRK-AC-002：同一异常重复触发时按规则关联既有未关闭事项，不产生无法解释的重复工单。
- KNW-AC-001：知识检索只返回有权且有效的版本，AI 回答可定位到原知识条目。
- UX-AC-001：交付范围内不存在看似可用但点击无实际结果且无说明的上传、下载或 AI 按钮。
