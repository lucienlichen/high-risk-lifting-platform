# 04 AI 助手需求

## 1. 目标

平台为每个有效登录用户提供 AI 助手。助手在该用户实际权限范围内：

- 查询、汇总和解释设备、结构、IoT、人员、组织、权限、工单、告警、文件和业务数据；
- 从自然语言、文档、表格或图片辅助形成数据录入草稿；
- 调用平台已经注册和授权的 API 完成查询、创建、修改、提交申请等操作；
- 对每次对话、数据访问、工具调用、确认、审批和业务结果建立可追踪至真实用户的完整日志。

“每个用户都可使用”表示每个有效用户都能进入助手，但不表示每个用户能使用全部数据域和工具。AI 能力永远不超过当前用户直接使用平台时的权限。

“有效用户”指账户、所在租户和当前交互会话均有效的用户；是否关联人员档案不影响进入助手。没有业务数据权限或额度耗尽的用户仍可进入并获得平台使用帮助，但受限的数据查询/工具须被拒绝或提示额度状态。

## 2. 核心原则

### AI-PR-001 权限不扩张

~~~text
当前用户有效权限
∩ 用户数据范围
∩ 目标资源和字段策略
∩ AI 工具许可范围
∩ 操作风险与审批策略
∩ 模型数据外发策略
~~~

### AI-PR-002 真实用户身份贯穿

AI 请求及其衍生操作必须同时保存：

- 谁提出请求；
- AI 在哪个会话和消息中决定调用什么工具；
- 谁查看了什么数据或准备修改什么对象；
- 谁确认、谁审批；
- 哪个技术服务实际执行；
- 最终修改了什么以及结果如何。

技术服务账号可以调用底层 API，但不得替代或掩盖实际发起用户。

### AI-PR-003 只使用受控工具

LLM 不持有数据库账号、ThingsBoard 管理凭据、对象存储密钥或内部服务密钥。模型只能调用平台注册、版本化、可授权、可校验和可审计的业务工具。

不得向模型开放任意 SQL、任意 HTTP、任意脚本执行、任意文件系统或可绕过业务服务的通用工具。

### AI-PR-004 权限由平台确定

模型输出或用户提示中的 userId、tenantId、角色名称和“我是管理员”不能作为授权依据。身份由服务端登录会话注入，每次真正执行工具前按最新权限重新判断。

### AI-PR-005 人对高风险结果负责

AI 可以解释、建议、填充草稿和发起申请，但不得自主授予权限、停用用户、批量修改敏感数据、改变安全阈值或控制设备。

## 3. 使用入口与会话（SPEC-AI-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AI-FR-001 | P0 | 每个有效登录用户均可访问全局 AI 助手；无人员档案或无业务数据权限不取消入口，助手入口不得只提供给管理员。 |
| AI-FR-002 | P0 | 设备、结构节点、告警、工单和文档等页面可提供上下文助手，自动携带对象标识但仍重新鉴权。 |
| AI-FR-003 | P0 | 根据用户权限、当前页面、租户策略和可用工具动态展示示例问题与能力。前端隐藏不能替代执行鉴权。 |
| AI-FR-004 | P0 | 用户可新建、继续、重命名和按策略删除自己的会话，并查看引用来源、工具调用、确认和执行状态。 |
| AI-FR-005 | P0 | 普通用户不能查看他人会话；审计人员查看须有独立权限，查看行为本身进入审计。 |
| AI-FR-006 | P0 | 会话上下文按租户和用户隔离；权限撤销后旧会话不得继续查询或把原受限数据再次提交给模型。退出后以另一租户账户登录须建立全新租户上下文，不能复用原工具计划/RAG 缓存。 |
| AI-FR-007 | P1 | 支持会话收藏、受控导出、反馈和用户纠错，具体保留策略待确认。 |
| AI-FR-008 | P0 | 历史回答中的资源链接、下载和重新执行始终按当前权限鉴权；权限撤销后历史正文如何展示由数据等级和保留策略决定，不得假定能收回用户已经看过的信息。 |
| AI-FR-009 | P0 | AI 会话和工具调用记录来源应用；跨应用查询必须调用目标应用公开工具，并同时校验租户已开通应用和用户目标应用权限。 |

## 4. 受控查询（SPEC-AIQ-01）

### 4.1 查询数据域

| 数据域 | 首期候选能力 | 关键限制 |
|---|---|---|
| 设备 | 查找设备、主档、组织、责任关系和生命周期 | 按组织/设备范围 |
| 物理结构/部件 | 查询结构树、节点、当前/历史安装部件、模板来源和关联资源 | 按设备、节点及部件权限和生效时间 |
| IoT | 最新值、历史趋势、告警、覆盖率和数据质量 | 限时间/点数，标明新鲜度 |
| 人员 | 责任人、班组、岗位、资质和受控联系方式 | 字段级权限和脱敏 |
| 组织 | 组织层级、设备归属和职责关系 | 不跨租户/授权分支 |
| 权限 | 解释当前用户为何可见或不可见某能力 | LLM 不做最终授权决定 |
| 巡检/检验/维修/工单 | 查询、汇总、跟踪和草拟 | 按参与、负责和组织范围 |
| 告警/隐患/风险 | 状态、证据、责任和闭环进度 | 不替代人工风险责任判断 |
| 文件/知识 | 检索手册、报告、图片说明和标准 | 文档 ACL、版本与引用 |
| 采集/处理 | 查询采集批次、OCR/ETL 状态、结构化结果、质量和数据谱系 | 须获数据处理应用及工具权限 |
| 业务统计 | 授权范围内的跨设备/组织统计 | 防止小样本反推敏感信息 |

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIQ-FR-001 | P0 | AI 通过领域工具查询，不直接访问数据库或 IoT 管理接口。 |
| AIQ-FR-002 | P0 | 跨设备—结构—点位—告警—工单—人员—文档查询时，逐个资源和字段检查权限。 |
| AIQ-FR-003 | P0 | 设备可见不自动等于关联人员全部字段可见，也不自动等于关联文件可下载。 |
| AIQ-FR-004 | P0 | 事实型回答提供可定位来源、查询时间和数据范围，并区分平台事实、文档内容、用户输入和 AI 推断。 |
| AIQ-FR-005 | P0 | 权限不足时拒绝且不泄露其他租户资源是否存在；可在授权范围内说明申请何种业务权限。 |
| AIQ-FR-006 | P0 | 每次查询限制最大记录数、设备/点位范围、遥测时间窗口、文档片段和调用频率。 |
| AIQ-FR-007 | P0 | 无结果、工具失败、数据不足或来源冲突时明确说明，不编造平台数据。 |

### 4.2 实时/时序数据回答

涉及设备当前状态时，工具结果和 AI 回答至少包含：

- 是否配置实时接入、是否部分接入及覆盖范围；
- 接入生命周期和数据运行状态；
- 最后测量时间、最后接收时间；
- 数据质量、有效/预期点位数；
- 数据源、结构节点和查询时间。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIQ-FR-010 | P0 | 未接入实时数据时，AI 不得回答“设备当前运行正常”。 |
| AIQ-FR-011 | P0 | 数据延迟或中断时说明最后有效时间，不把旧值表述为当前值。 |
| AIQ-FR-012 | P0 | 部分接入时说明结论仅覆盖哪些节点/点位，不能外推整机状态。 |
| AIQ-FR-013 | P0 | 大范围历史查询使用聚合或异步任务，AI 不可绕过查询上限。 |

### 4.3 人员与权限数据

人员字段至少分：

- 普通业务信息：姓名、部门、岗位、班组；
- 受限信息：工作电话、邮箱、排班和资质；
- 禁止进入模型：密码、令牌、密钥、私人联系方式、完整证件号码等。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIQ-FR-020 | P0 | 返回模型前按当前用户字段权限删除、掩码或摘要人员数据。 |
| AIQ-FR-021 | P0 | AI 可以调用确定性权限解释工具，但不能自行决定、模拟或覆盖授权结果。 |
| AIQ-FR-022 | P0 | 权限关系、敏感人员查询和批量统计使用强化审计，并防止通过多轮问答逐步重建禁止字段。 |

## 5. 数据录入（SPEC-AIW-01）

### 5.1 录入方式

AI 可从以下输入提取结构化数据：

- 用户自然语言描述和对话式补充；
- 平台表单；
- 用户上传的文档、表格、图片和检测报告；
- 用户有权查看的既有业务对象。

首期候选对象包括设备建档、结构节点补充、人员业务信息、巡检/检验记录、告警处置、隐患、维修/工单和文件元数据。最终开放清单和风险等级需由用户确认。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIW-FR-001 | P0 | AI 提取结果默认形成结构化草稿，不直接写入正式业务数据。 |
| AIW-FR-002 | P0 | 草稿展示目标对象、操作类型、字段值、原文对应关系、缺失项、格式问题、重复/冲突和敏感字段提示。 |
| AIW-FR-003 | P0 | 用户可修改草稿；正式提交前展示字段差异或副作用预览，包括目标/范围、状态转换、接收人、下游通知/任务、预计数据量、外部影响和是否可撤销。 |
| AIW-FR-004 | P0 | 执行时复用正式业务 API 的必填、枚举、唯一、引用、版本、权限、状态机和审批校验。 |
| AIW-FR-005 | P0 | AI 不能通过提示词跳过必填、伪造确认人或绕过业务校验。 |
| AIW-FR-006 | P0 | 执行结果逐项返回成功/失败、对象编号、变化摘要、失败原因、操作编号和审计编号。 |
| AIW-FR-007 | P0 | 批量操作支持预览、数量上限、幂等键和逐项结果，状态未知时不得静默重复写入。 |
| AIW-FR-008 | P1 | 允许用户保存可复用录入指令/模板，但模板不保存明文敏感信息并受版本控制。 |

## 6. API 工具和风险分级（SPEC-AIT-01）

### 6.1 工具注册

每个 AI 工具必须注册：

- 工具名称、版本、业务所有者和用途；
- 允许的权限、数据范围及目标资源；
- 输入输出 Schema 和字段数据等级；
- 读取/写入性质、风险等级；
- 是否要求确认、重新认证或审批；
- 幂等、超时、记录/批量上限和补偿规则；
- 允许发送给模型的字段、脱敏和审计规则。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIT-FR-001 | P0 | 只有已启用、版本明确并通过安全评审的工具可供模型调用。 |
| AIT-FR-002 | P0 | 工具计划形成时预检查，真正执行前按最新用户权限、资源状态和参数再次校验。 |
| AIT-FR-003 | P0 | 工具参数中的用户/租户身份不能覆盖服务端身份上下文。 |
| AIT-FR-004 | P0 | 写工具使用正式业务 API、幂等键和并发版本；不得另建一套低约束 AI 写入通道。 |
| AIT-FR-005 | P0 | 参数、数据版本、权限或工具版本变化后，已有确认失效并要求重新确认。 |
| AIT-FR-006 | P1 | 支持按租户、角色和用户配置工具额度、启停、时间段和数据外发策略。 |
| AIT-FR-007 | P0 | 工具使用应用命名空间并声明所属应用；租户未开通或用户无权进入该应用时工具不可调用。 |

### 6.2 风险分级

| 等级 | 示例 | AI 允许行为 |
|---|---|---|
| R0 普通读取 | 设备普通主档、普通知识条目 | 鉴权后执行并记录 |
| R1 敏感读取 | 人员联系方式、权限关系、批量导出 | 二次校验、脱敏、限量、强化审计，必要时确认 |
| R2 可逆写入 | 创建巡检/工单、添加备注、修改普通主档 | 生成草稿/差异，用户通过服务端确定性确认后执行 |
| R3 高风险 | 权限变更、用户停用、阈值、批量敏感更新、设备命令 | AI 只形成申请；重新认证/审批后由确定性流程执行 |
| R4 禁止 | 密码/密钥、任意 SQL/HTTP/脚本、绕权访问 | 永不向模型开放 |

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIT-FR-010 | P0 | R2 操作未经实际用户明确确认不得执行。 |
| AIT-FR-011 | P0 | R3 操作默认不得由模型直接执行，审批人与发起人是否必须分离待确认。 |
| AIT-FR-012 | P0 | 首期不注册设备控制工具；后续如开放，AI 只能创建控制申请，不能构造/发送命令，获批后由独立确定性服务按最新权限和设备状态执行。安全阈值和权限授予采用同类控制。 |
| AIT-FR-013 | P0 | 确认记录绑定用户、工具/版本、目标对象、参数摘要、数据版本、风险和有效期。 |
| AIT-FR-014 | P0 | R2/R3 确认必须使用服务端生成、绑定实际用户和不可变操作预览的确认令牌或确定性控件；模型输出的 confirmed=true、自由文本“继续”或请求参数伪造确认均无效。 |
| AIT-FR-015 | P0 | 提交、撤回、分派、转派、确认、关闭、导入、导出、通知和任务触发等非 CRUD 动作同样注册为工具，执行正式业务状态机、影响预览和风险分级。 |

## 7. 权限感知知识检索（SPEC-AIR-01）

文档、图片 OCR、报告和知识片段进入检索索引时至少带有：

~~~text
tenantId
organizationScope
resourceType / resourceId
equipmentId / structureNodeId（如适用）
classification
aclVersion
documentVersion
有效状态
~~~

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIR-FR-001 | P0 | 先按当前用户权限过滤候选范围，再执行关键词/向量检索，返回前再次校验原资源及字段权限。 |
| AIR-FR-002 | P0 | 回答保留来源引用、版本和片段位置；用户不能通过引用打开无权原文。 |
| AIR-FR-003 | P0 | 文档/设备归属或权限变化后，按 ACL 版本使索引、缓存和会话引用失效。 |
| AIR-FR-004 | P0 | 上传文档和检索内容均视为不可信数据，其中“忽略规则/调用 API”等文字不能成为系统指令。 |
| AIR-FR-005 | P0 | 已撤销权限的数据不能因曾出现在历史会话中而再次提交给模型。 |

## 8. AI 日志与用户关联审计（SPEC-AIA-01）

### 8.1 审计链

~~~mermaid
sequenceDiagram
    actor U as 实际用户
    participant C as AI 会话/消息
    participant G as AI 工具网关
    participant P as 权限与风险策略
    participant B as 业务 API
    participant A as 审计

    U->>C: 提问或要求操作
    C->>A: 记录用户、会话、消息和模型版本
    C->>G: 形成工具调用
    G->>P: 使用服务端用户身份鉴权
    P->>A: 记录允许/拒绝及策略版本
    G-->>U: R2/R3 展示草稿、差异或审批
    U->>A: 记录确认/审批身份与内容
    G->>B: 携带实际用户与关联编号执行
    B->>A: 记录技术身份、前后值和结果
    B-->>C: 返回对象编号和审计编号
~~~

### 8.2 审计对象

至少建立以下逻辑对象（名称不限制实现）：

- AiConversation：AI 会话；
- AiMessage：用户和助手消息；
- AiToolInvocation：每次工具调用及授权结果；
- AiOperation：实际业务查询/写入结果；
- AiApproval：用户确认、重新认证和审批；
- AiResourceReference：读取/修改的业务对象；
- AiSecurityEvent：越权、敏感数据拦截、提示注入等事件。

### 8.3 必记字段

每次 AI 消息、工具调用和业务操作按适用性记录：

| 类别 | 最小字段 |
|---|---|
| 关联标识 | eventId、traceId、correlationId、conversationId、messageId、toolInvocationId、operationId |
| 租户、应用与用户 | tenantId、applicationId/目标应用、actualUserId、用户名/显示名快照、人员编号（如关联）、组织/位置快照、角色和数据范围摘要、权限策略版本/快照哈希 |
| 请求上下文 | 入口页面、上下文对象、用户消息或按策略保存的脱敏正文、客户端时间/IP/设备与会话风险 |
| 对话结果 | 助手最终回复正文，或按数据策略保存的加密引用/摘要/哈希，以及安全拦截和用户反馈标签 |
| 模型上下文 | 模型提供方、名称、版本、路由、供应方请求/响应编号、系统提示版本、温度等关键配置、token 用量及可选成本 |
| 工具上下文 | 工具名称/版本、查询条件和授权范围、受控参数、参数摘要/哈希、目标对象类型和编号、风险等级 |
| 读取结果 | 返回记录数、字段清单/等级、来源/版本/新鲜度、工具原始结果安全引用或摘要/哈希、脱敏策略及实际发送给模型的数据摘要 |
| 授权与风控 | 允许/拒绝、命中策略、字段脱敏、数据外发等级、拒绝原因 |
| 确认与审批 | 确认人、确认时间、确认内容摘要、重新认证结果、审批人/意见/时间 |
| 执行与变更 | 技术执行身份、对象前后版本、受控前后值、字段 diff、幂等键、开始/结束/耗时 |
| 结果 | 成功、失败、部分成功、状态未知、错误码、重试、回滚/补偿和最终对象入口 |

说明：

- 用户名、组织和权限采用“稳定标识 + 当时快照/版本”，即使用户后来改名、调岗或停用，仍能解释当时是谁、以何权限操作。
- 密码、令牌、密钥和禁止字段不得写入日志；其他敏感字段按策略脱敏、加密或只记哈希。
- 不记录或展示模型内部思维链；可记录实际输入输出、工具参数、策略决策和业务结果。

### 8.4 审计行为要求

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIA-FR-001 | P0 | 每条用户消息都关联实际用户；每次查询、工具调用、拒绝和业务结果都沿同一关联编号串联。 |
| AIA-FR-002 | P0 | AI 操作不能只记录“AI 助手”，必须同时记录实际发起用户和当时组织/权限上下文。 |
| AIA-FR-003 | P0 | 底层服务账号执行时同时记录技术执行身份，不得覆盖实际用户字段。 |
| AIA-FR-004 | P0 | 用户在会话中可查看自己发起的工具操作、确认及结果；权限内管理员可按用户、会话、模型、工具、对象、风险和结果检索。 |
| AIA-FR-005 | P0 | 业务对象详情可反向显示“用户 A 通过 AI 发起，经 B 确认/审批，由服务 C 执行”。 |
| AIA-FR-006 | P0 | 普通会话删除不删除依法/按策略需保留的操作审计和安全事件。 |
| AIA-FR-007 | P0 | AI 审计与普通会话展示数据分离，采用仅追加或等效防篡改控制；访问和导出日志也被审计。 |
| AIA-FR-008 | P0 | 工具失败、无权限、参数校验失败和部分成功同样记录，且能判定是否产生业务变更。 |
| AIA-FR-009 | P1 | 支持异常查询、越权尝试、高失败率、敏感工具和成本异常的检测与提醒。 |
| AIA-FR-010 | P0 | 分别授权 AI 审计检索、对话正文查看和导出；平台管理员不天然拥有完整正文权限，任何查看/导出再次留痕。 |

## 9. 数据外发、隐私和模型路由（SPEC-AIS-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIS-FR-001 | P0 | 数据按允许外部模型、仅私有模型、仅脱敏摘要、禁止进入模型进行分类。 |
| AIS-FR-002 | P0 | 模型路由不得降低数据等级；工具只返回完成当前任务所需的最少字段和记录。 |
| AIS-FR-003 | P0 | 提示、响应、会话、工具参数、缓存和日志采用独立访问控制和可配置保留期。 |
| AIS-FR-004 | P0 | 模型、工具或索引不可用不影响设备接入、告警和人工业务功能。 |
| AIS-FR-005 | P0 | 外部模型供应方不得获得平台数据库或 IoT 凭据，且其数据使用规则须满足平台策略。 |
| AIS-FR-006 | P1 | 支持按租户设置模型路由、预算、速率、数据域和工具配额。 |

## 10. 管理与运行（SPEC-AIO-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIO-FR-001 | P0 | 管理员可查看已启用模型、提示模板、工具及其版本、风险等级和业务所有者。 |
| AIO-FR-002 | P0 | 模型、提示、工具和权限策略变更必须版本化、审批（按风险）并可回溯。 |
| AIO-FR-003 | P0 | 支持用量、成功率、拒绝率、工具错误、延迟和安全事件监控。 |
| AIO-FR-004 | P0 | 长耗时工具与对话响应分离，显示进度、最终状态和通知；用户离开页面后仍可查询结果。 |
| AIO-FR-005 | P1 | 支持基于脱敏测试集的工具/回答质量评估、回归测试和用户反馈闭环。 |
| AIO-FR-006 | P0 | 异步操作在每次产生业务副作用前按最新用户、权限、确认/审批、对象版本和归属重新校验；不满足时取消或转人工。已明确移交的系统流程可继续，但须保留原发起用户、移交依据和系统执行身份。 |

## 11. 失败与异常

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AIE-FR-001 | P0 | 无权限时拒绝且不暴露资源存在性或其他租户名称。 |
| AIE-FR-002 | P0 | 数据不足、过期、覆盖率低或文档版本失效时明确限制，不编造结果。 |
| AIE-FR-003 | P0 | 草稿生成后目标对象发生变化时检测版本冲突，显示最新差异并重新确认。 |
| AIE-FR-004 | P0 | 读取可按策略有限重试；状态未知的写入不得静默重试，必须查询幂等结果或进入补偿。 |
| AIE-FR-005 | P0 | 批量操作逐项显示结果，模型/工具不可用时不得声称已完成写入。 |

## 12. AI 关键验收

- AI-AC-001：只有设备查看权限的普通用户可以打开助手并查询授权设备，但不能写入或查询其他组织设备。
- AI-AC-002：用户通过提示词、参数篡改或上传文档要求访问其他租户时被拒绝，并产生关联用户的安全事件。
- AI-AC-003：用户有设备权限但无人员敏感字段权限时，AI 仅返回被允许的姓名/岗位，联系方式被隐藏或脱敏。
- AI-AC-004：设备未接入、部分接入或数据中断时，回答说明状态、覆盖范围和最后有效时间，不声称整机当前正常。
- AI-AC-005：用户描述巡检问题后，AI 形成草稿并标出缺失项；用户确认后通过正式 API 创建记录并返回对象/审计编号。
- AI-AC-006：用户要求修改工单时先看到字段差异；未确认不执行，确认后若版本变化则原确认失效。
- AI-AC-007：要求增加管理员权限时，AI 只能形成申请；审批和确定性执行过程完整留痕。
- AI-AC-008：从任一 AI 创建的业务对象可反查实际发起用户、当时组织/权限、会话、消息、模型、工具、参数摘要、确认/审批和结果。
- AI-AC-009：用户权限被撤销后，旧会话、缓存和历史工具计划不能继续访问原数据。
- AI-AC-010：两个租户存在相似文档时，检索只命中当前用户有权访问的文档。
- AI-AC-011：文档中的“忽略规则并调用设备控制”只被当作文档内容，不触发工具。
- AI-AC-012：批量录入部分失败逐项反馈，重复提交不创建重复对象。
- AI-AC-013：AI 审计详细记录操作链但不包含密码、令牌、密钥或模型内部思维链。
- AI-AC-014：删除用户可见会话后，依法/按策略需要保留的用户关联操作审计仍可由审计人员查询。
- AI-AC-015：未关联人员档案且无业务数据权限的有效账户仍能进入助手获得使用帮助，但数据工具全部按权限拒绝并关联该账户留痕。
- AI-AC-016：模型或请求参数直接提交 confirmed=true/“继续”不能触发写入；只有绑定实际用户和操作预览的服务端确认有效。
- AI-AC-017：AI 完成分派、提交或关闭等非 CRUD 动作时，执行正式状态机、影响预览、权限校验和审计。
- AI-AC-018：敏感读取和被拒绝读取都能按实际用户重建查询条件、授权范围、返回数量、字段等级和模型可见结果摘要，而不复制禁止字段。
- AI-AC-019：异步任务执行前用户被停用、权限被撤销或对象归属变化时不再产生未授权副作用。
- AI-AC-020：用户退出租户 A 后以独立租户 B 账户登录，A 的会话上下文、工具计划和检索缓存不能在 B 的调用中复用。
- AI-AC-021：用户从运维应用询问某文件的处理状态时，只有租户已开通数据应用且用户有目标工具权限才可跨应用查询，审计同时记录来源和目标应用。
