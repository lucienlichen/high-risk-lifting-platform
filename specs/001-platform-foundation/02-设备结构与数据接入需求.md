# 02 设备结构与数据接入需求

## 1. 目标与边界

本领域解决三件相互关联但必须解耦的事情：

1. 设备是什么、属于谁、由哪些物理部分组成；
2. 传感器、PLC 点位、文件、图片和业务记录与哪个物理部分相关；
3. 数据从哪里来、如何映射、是否仍新鲜以及如何高效保存和查询。

设备主档不依赖 IoT 连接存在。设备没有实时数据时仍是完整业务对象；IoT 平台中的连接对象也不必一对一等同于业务设备。

## 2. 概念关系

~~~mermaid
flowchart LR
    CT["设备类别"] --> ST["物理结构模板版本"]
    ST --> EI["设备实例"]
    EI --> NI["结构节点实例"]
    NI --> RA["文档 / 图片 / 业务记录"]
    NI --> SA["传感器资产"]
    CA["可更换部件资产"] --> CI["部件安装关系（有生效时间）"]
    CI --> NI

    AT["接入模板版本"] --> DS["数据源实例"]
    DS --> SP["源点位 / PLC 标签"]
    SP --> SC["传感器通道（可选）"]
    SC --> MP["业务测点"]
    SP -. "无独立传感器时" .-> MP
    MP --> PB["结构绑定（有版本）"]
    PB --> NI
    MP --> TV["当前值 / 时序值 / 质量"]

    TB["IoT 底座实体"] -. "标识映射" .-> DS
~~~

关键约束：

- 结构模板描述“设备由什么组成”。
- 接入模板描述“数据如何进入并映射到结构”。
- 传感器是可选的物理资产；被动传感器不要求在 ThingsBoard 中单独建 Device。
- PLC/网关可作为数据源，一个数据源的不同点位可绑定不同设备或不同结构节点。
- 业务设备与数据源通过点位绑定形成多对多关系，不以某个 IoT 平台实体名称代替业务关系。
- 结构节点表示稳定的物理位置/功能层级；需要独立追踪序列号和更换历史的减速机、制动器等作为可更换部件资产安装到节点。
- 源点位表示 PLC/网关中的技术地址，业务测点表示“某结构位置的某个可观测量”；地址、传感器或部件更换不能静默改写业务测点历史。

## 3. 设备类别与主档（SPEC-EQM-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| EQM-FR-001 | P0 | 支持维护设备类别、子类别及其编码、名称、状态和说明。 |
| EQM-FR-002 | P0 | 设备实例至少具有业务编号、名称、类别、业务生命周期、资产/使用/维保组织、位置、责任人和关键日期。 |
| EQM-FR-003 | P0 | 设备使用平台生成的全局唯一、不可变内部 ID，并显式归属租户；业务编号在租户内唯一，旧应用 ID、IoT 标识、注册号和出厂编号作为有类型的外部标识维护。 |
| EQM-FR-004 | P0 | 支持手工创建、模板创建、批量导入和经批准的 API 建档，并逐项校验重复及必填信息。 |
| EQM-FR-005 | P0 | 设备业务生命周期、设备运行状态、接入生命周期和数据运行状态作为四个独立维度；运行状态记录来源/时间，停用或报废不删除历史。 |
| EQM-FR-006 | P0 | 设备可以标记无实时接入、人工/文件数据、周期接入、流式接入或多种方式并存。 |
| EQM-FR-007 | P0 | 设备详情必须明确显示实时接入覆盖范围和数据新鲜度，不能用单一“在线”混合表达运行与连接。 |
| EQM-FR-008 | P1 | 支持设备复制、批量变更、资产转移及带审批的报废流程。 |
| EQM-FR-009 | P0 | 外部标识映射包含 tenantId、sourceSystem、identifierType、value、equipmentId 和状态；匹配不确定时不得自动合并设备。 |
| EQM-FR-010 | P0 | 数据采集处理和智能运维应用必须使用同一公共 equipmentId，应用特有字段进入版本化扩展对象而非复制设备主档。 |

## 4. 设备物理结构模板（SPEC-EQT-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| EQT-FR-001 | P0 | 支持按设备类别建立树形物理结构模板，例如整机—金属结构/运行机构—减速机/制动器。 |
| EQT-FR-002 | P0 | 模板节点至少定义稳定编码、名称、节点类型、父节点、顺序、是否必需、允许数量及说明。 |
| EQT-FR-003 | P0 | 节点可声明允许关联的资源类型，包括传感器、数据点、PLC 标签、文档、图片、检验、告警、工单和维修记录。 |
| EQT-FR-004 | P0 | 模板族使用稳定标识归集版本；每个版本/修订支持草稿、审核中、已发布、已废止状态，发布前校验唯一根节点、编码、层级、数量和必需项。 |
| EQT-FR-005 | P0 | 已发布版本不可原位覆盖，任何修改从该版本派生新的草稿版本；已有设备继续引用创建时版本。 |
| EQT-FR-006 | P0 | 支持从已有模板/版本复制为草稿，保留来源关系。 |
| EQT-FR-007 | P0 | 模板版本应能记录创建人、发布人、变更说明、发布时间和节点差异。 |
| EQT-FR-008 | P1 | 可配置模板发布审核，并比较两个版本的新增、删除、移动和属性变化。 |
| EQT-FR-009 | P1 | 如需要表达传动、供电、控制或安装等横向关系，应在不破坏主结构树的前提下建立有类型的节点关系；是否首期支持待确认。 |

## 5. 设备及结构实例（SPEC-EQI-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| EQI-FR-001 | P0 | 从已发布模板版本创建设备时，生成可独立识别的结构节点实例，并保留模板、版本和节点来源。 |
| EQI-FR-002 | P0 | 每个结构节点可查看基本信息、子结构、关联传感器/点位、文件图片和业务记录。 |
| EQI-FR-003 | P0 | 经授权可新增、修改、移动或停用实例节点；必须清晰标注与模板的差异并记录变更历史。 |
| EQI-FR-004 | P0 | 删除或停用已有点位、文件或业务记录关联的节点前必须提示冲突，不得静默丢失关联。 |
| EQI-FR-005 | P0 | 文档、图片、传感器、PLC 点位、采集批次、结构化数据产品和业务记录可关联整机或任意结构层级并支持反查；超出模板约束的关联须标为实例偏差并按策略确认/审批。 |
| EQI-FR-006 | P0 | 一个资源可按业务需要关联多个节点，但须标记主要关联和关联用途。 |
| EQI-FR-007 | P0 | 结构节点及资源绑定变化应可追溯至用户、时间、来源和变更前后关系。 |
| EQI-FR-008 | P1 | 设备可受控升级到新模板版本；升级前显示差异、实例偏差和绑定冲突，由用户确认处理。 |
| EQI-FR-009 | P1 | 模板升级不得自动删除实例独有节点或已有业务数据。 |

|---|---:|---|
| AST-FR-001 | P0 | 支持按需维护传感器、PLC、网关等资产的业务编码、型号、厂商、序列号、状态和安装信息。 |
| AST-FR-002 | P0 | 传感器可安装到某结构节点，并保留安装、拆卸、更换和校准历史。 |

### 6.1 可更换部件资产与安装（SPEC-CMP-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| CMP-FR-001 | P0 | 物理结构模板节点表示稳定位置/功能，模板可标记该节点是否需要独立追踪实际部件；未要求序列化追踪的普通结构不强制创建部件资产。 |
| CMP-FR-002 | P0 | 被独立追踪的减速机、制动器、卷筒等部件资产拥有不可变内部 ID，并可维护类别、型号、厂商、序列号、状态和来源。 |
| CMP-FR-003 | P0 | 部件通过安装关系进入结构节点，记录安装/拆卸时间、原因、执行人和来源；同一位置的有效安装区间不得发生未经解释的冲突。 |
| CMP-FR-004 | P0 | 时序、文件、检验、故障和维修可同时引用结构位置及实际部件；只引用位置的历史数据按当时有效安装关系解释，不因换件归到新部件。 |
| CMP-FR-005 | P0 | 更换部件不改变稳定结构路径和业务测点身份，不覆盖旧部件、旧绑定、旧证据或历史结论。 |
| CMP-FR-006 | P1 | 支持备件、翻修、跨设备移装和部件全生命周期追溯，首期深度按设备类别确认。 |

## 7. 接入模板与实例（SPEC-DAT-01）

### 7.1 接入模板

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DAT-FR-001 | P0 | 支持版本化接入模板，用于快速生成数据源、点位、映射、单位换算、质量和告警配置草稿。 |
| DAT-FR-002 | P0 | 模板可定义数据源槽位、接入方式、协议参数模式、预期结构节点编码、点位编码、数据类型、单位和预期上报周期。 |
| DAT-FR-003 | P0 | 模板可定义点位解析、量程、精度、合法值、缺失/异常值处理、延迟/中断阈值和默认告警规则。 |
| DAT-FR-004 | P0 | 模板只保存凭据引用或凭据需求，不保存可被普通用户、导出文件或 AI 读取的明文密钥。 |
| DAT-FR-005 | P0 | 接入模板采用稳定模板族和版本/修订；已发布版本不可原位修改，新版本不自动覆盖既有接入实例。 |
| DAT-FR-006 | P0 | 实例化后允许在授权范围内覆盖连接参数、点位地址、阈值和映射，并明确标识偏差。 |
| DAT-FR-007 | P1 | 支持从已验证的接入实例反向生成模板草稿。 |

### 7.2 数据源与接入实例

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DAT-FR-010 | P0 | 数据源至少支持直连设备、传感器直连、PLC、网关和第三方平台等来源。 |
| DAT-FR-011 | P0 | 每个数据源记录类型、接入方式、所属组织、标识映射、连接配置引用和生命周期。 |
| DAT-FR-012 | P0 | 数据源可关联一个或多个设备；设备可使用一个或多个数据源。 |
| DAT-FR-013 | P0 | 支持无接入、人工录入、文件批量、周期采集和流式采集，并保持来源可辨识。 |
| DAT-FR-014 | P0 | 接入生命周期至少包括未配置、已配置、验证中/试运行、已启用、已暂停和已退役。 |
| DAT-FR-015 | P0 | 试运行前完成凭据引用、必填配置、网络/连接（如可测试）、Schema 和静态映射预检；协议不支持点位发现时不得因此判定失败。 |
| DAT-FR-016 | P0 | 暂停、退役和从未启用的数据源不产生“数据中断”技术事件，但历史数据仍可按权限查询。 |
| DAT-FR-017 | P0 | 接入配置、凭据引用、模板版本、点位和映射变更须版本化并审计。 |
| DAT-FR-018 | P1 | 支持配置灰度启用、回滚和接入迁移，迁移不得造成点位身份混淆。 |
| DAT-FR-019 | P0 | 试运行使用真实或经批准的样本数据验证解析、点位映射、设备时间、质量及频率；通过后进入已启用，失败时保留分类结果并可修正重试。 |

## 8. 点位与结构绑定（SPEC-PNT-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| PNT-FR-001 | P0 | 明确区分 SourcePoint（PLC/网关地址或标签）、可选 SensorChannel（物理传感器通道）和 MeasurementPoint（稳定业务测点），三者使用独立标识和版本化映射。 |
| PNT-FR-002 | P0 | 每条有效业务测点绑定须明确租户、MeasurementPoint、设备、结构节点、可选部件资产、用途和生效时间。 |
| PNT-FR-003 | P0 | 同一 PLC 的不同 SourcePoint 可映射为不同 MeasurementPoint 并绑定不同设备/节点；查询和聚合不得串用。 |
| PNT-FR-004 | P0 | 一个 MeasurementPoint 默认只设一个主要结构绑定；如需多节点共用，应使用显式的次要绑定和用途，规则待确认。 |
| PNT-FR-005 | P0 | 源地址、传感器通道、业务测点和结构/部件绑定分别保留时间有效区间；换传感器、换地址、换部件或改绑节点时，历史数据按当时映射解释。 |
| PNT-FR-006 | P0 | 覆盖率按预期业务测点或结构节点计算，并展示分母、分子、未接入项和统计时间。 |
| PNT-FR-007 | P0 | 设备部分接入时必须显示“部分接入”，任何评估结论须说明使用的节点/点位覆盖范围。 |
| PNT-FR-008 | P1 | 支持源点位/业务测点批量导入、模板映射预览、冲突检测和逐项结果。 |
| PNT-FR-009 | P0 | SourcePoint 至少维护数据源、源标签/地址、原始类型、采集方式和状态；地址被复用时不能继承上一业务测点语义。 |
| PNT-FR-010 | P0 | MeasurementPoint 至少维护稳定编码、业务名称、观测量、标准类型/单位、预期周期或服务等级、质量规则和状态。 |
| PNT-FR-011 | P0 | 点类型至少区分读数、事件、派生结果和命令；命令点与遥测查询接口、权限及凭据隔离，并按高风险操作管理。 |
| PNT-FR-012 | P0 | 周期/批量采集明确计划频率、允许延迟和数据可用时限，不因存在周期数据就显示为实时在线。 |

## 9. 运行状态、数据质量与新鲜度（SPEC-DQS-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DQS-FR-001 | P0 | 数据运行状态至少区分不适用、等待数据、正常、延迟、中断和异常。 |
| DQS-FR-002 | P0 | 根据点位预期周期及可配置容差判断新鲜度，保存状态变化时间和原因。 |
| DQS-FR-003 | P0 | 同时保存测量时间和平台接收时间；状态展示不得仅使用服务器写入时间。 |
| DQS-FR-004 | P0 | 数据值须带来源、质量标记和必要的解析/换算版本，至少能区分有效、缺失、超量程、解析失败、重复、迟到和人工修正。 |
| DQS-FR-005 | P0 | 设备汇总状态由可解释规则计算，并可下钻到异常数据源和点位。 |
| DQS-FR-006 | P0 | 无实时接入设备显示“不适用/未接入”而非离线；文件或人工数据不能使设备变为实时在线。 |
| DQS-FR-007 | P0 | UI、报表、API 和 AI 回答均应提供最后有效时间、来源和覆盖范围。 |
| DQS-FR-008 | P1 | 支持数据质量统计、异常率、完整率、及时率和质量趋势。 |

## 10. 时序数据与查询（SPEC-TSDB-01）

### 10.1 持久化行为

| 编号 | 优先级 | 需求 |
|---|---:|---|
| TSDB-FR-001 | P0 | 时序数据从首期作为核心数据类型规划，逻辑上与设备主数据和业务事务数据分离管理。 |
| TSDB-FR-002 | P0 | 每个样本至少保存租户、数据源、SourcePoint、MeasurementPoint/映射版本、测量时间、接收时间、原始/标准化值或引用、质量和去重标识。 |
| TSDB-FR-003 | P0 | 支持数值、布尔、枚举及必要的文本/事件数据；图片和大文件进入文件存储，时序记录只保存引用及元数据。 |
| TSDB-FR-004 | P0 | 样本优先以“租户 + 数据源 + SourcePoint + 源事件/序列标识”去重；无源标识时使用约定时间/序列规则。同标识同内容幂等，同标识异内容进入冲突记录而不静默覆盖。 |
| TSDB-FR-005 | P0 | 统一时间语义，持久化使用统一时基，展示按用户/设备时区转换，并保留原设备时间及校时质量。 |
| TSDB-FR-006 | P0 | 支持原始数据、降采样/聚合数据和保留策略，任何聚合结论可追溯聚合规则和时间范围。 |
| TSDB-FR-007 | P0 | 历史绑定、单位或换算规则变化后，既有数据的解释方式必须明确，不能静默改写造成审计歧义。 |
| TSDB-FR-008 | P0 | 最新值查询与历史范围查询均须受租户、设备、结构和点位权限控制。 |
| TSDB-FR-009 | P1 | 支持按数据等级归档、恢复和合规删除，并保留操作审计。 |

### 10.2 查询能力

| 编号 | 优先级 | 需求 |
|---|---:|---|
| TSDB-FR-010 | P0 | 支持按设备、结构节点、部件、数据源、SourcePoint、MeasurementPoint 和时间范围查询当前值及历史值。 |
| TSDB-FR-011 | P0 | 支持最小、最大、平均、计数、首末值、变化量等按时间窗口聚合，并明确空值和坏质量数据规则。 |
| TSDB-FR-012 | P0 | 大范围查询应自动使用合适粒度或异步导出，避免一次返回不可控数据量。 |
| TSDB-FR-013 | P0 | 查询结果包含测量时间、接收时间、单位、质量、新鲜度和来源，不能只返回值。 |
| TSDB-FR-014 | P0 | 支持工作日期/工作循环等业务时间窗口查询，并保留其与自然时间的映射。 |
| TSDB-FR-015 | P1 | 支持多点位对齐、对比、派生指标和经版本管理的计算结果。 |
| TSDB-FR-016 | P0 | 点位历史默认按样本测量时间对应的有效绑定归属设备/结构并执行权限；按当前结构重新投影须作为独立、明确标识的查询。 |
| TSDB-FR-017 | P0 | 原始采集值不可被人工静默覆盖；人工修正形成带原因、用户、版本和原值引用的独立记录。迟到/乱序窗口及聚合重算规则可配置并可追溯。 |
| TSDB-FR-018 | P0 | 性能验收画像冻结采样频率、返回桶数、质量过滤、并发查询/订阅、冷热范围、缓存条件和峰值持续时间，不能仅以“100 点、适当聚合”描述。 |
| TSDB-FR-019 | P0 | 明确定义接收确认发生在边缘、消息队列还是持久化落盘，以及该确认覆盖的故障域；“已确认不丢失”与备份 RPO 分别验收。 |
| TSDB-FR-020 | P0 | 实时流与重连补传具有优先级、限流、隔离和积压恢复时限，补传压力不得让当前状态长期失真或阻塞其他租户。 |

### 10.3 性能验收基线

最终写入规模必须由“设备数 × 每设备点位数 × 上报频率 × 峰值系数 × 保留期”测算。本草案先定义可测试的服务目标，规模参数在 05 文档中待确认：

- 在约定峰值写入负载下不丢失已确认接收的数据，积压恢复后能保持去重和原测量时间。
- 单设备最新值查询 P95 不高于 2 秒。
- 单设备不超过 100 个点位的 24 小时趋势查询，采用适当聚合后 P95 不高于 3 秒。
- 单设备不超过 100 个点位的 30 天趋势查询，采用适当聚合后 P95 不高于 5 秒。
- 超出在线查询上限的跨设备、长周期原始数据使用异步任务，并显示进度、结果范围和审计编号。
- IoT 写入或查询压力不得阻塞登录、权限、工单和人工录入等核心业务事务。

这些指标是待确认的产品验收目标，不预先决定使用单库、独立时序库或 ThingsBoard 自带存储。

### 10.4 高频波形、声音与图像

减速机、车轮等振动/声音可能产生高频原始波形，不应简单等同于普通低频点值：

| 编号 | 优先级 | 需求 |
|---|---:|---|
| WAV-FR-001 | P0 | 高频采集至少区分连续/事件片段原始波形与从波形提取的特征值，普通趋势默认查询特征值。 |
| WAV-FR-002 | P0 | 原始片段记录设备、结构节点、传感器、起止时间、采样率、通道、质量、文件/对象引用和校验值。 |
| WAV-FR-003 | P0 | 异常特征、告警和诊断结果可追溯到对应事件前后原始波形/声音片段。 |
| WAV-FR-004 | P0 | 波形、声音和图像分别设置在线查询、下载、保留和归档策略，并执行设备/结构/文件权限。 |
| WAV-FR-005 | P1 | 支持受控播放/可视化、片段对比和特征重算；特征算法和版本可追溯。 |

## 11. IoT 规则事件与运维告警（SPEC-ALM-01）

本 Spec 区分两个对象：统一 IoT 服务产生不可丢失的技术规则事件（TelemetryRuleEvent），智能运维应用按规则把需要人工处置的事件转为或关联可处置业务告警（OperationalAlarm）。技术事件不承担分派/关闭流程，业务告警也不反向改写原技术事实。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| ALM-FR-001 | P0 | 统一 IoT 服务支持按点位、结构节点和设备配置阈值、组合、数据缺失及质量规则，并产生技术规则事件。 |
| ALM-FR-002 | P0 | 技术规则事件至少包含来源、设备、结构节点、点位、规则/版本、等级、触发值/条件、首次/最近时间、恢复时间和数据证据。 |
| ALM-FR-003 | P0 | 智能运维应用负责业务告警的确认、分派、处置、恢复确认和关闭，并保留与一个或多个技术事件的来源关系及完整时间线。 |
| ALM-FR-004 | P0 | 重复技术事件按确定规则合并、抑制或升级；业务告警使用独立去重/关联规则，不能产生无法处理的告警风暴。 |
| ALM-FR-005 | P0 | 暂停/退役接入和无实时接入设备不触发实时数据中断技术事件。 |
| ALM-FR-006 | P0 | 技术规则/抑制变更与业务告警确认/关闭分别由其权威服务鉴权和审计，任何同步不得形成双向状态覆盖。 |
| ALM-FR-007 | P0 | 业务告警支持关联统一问题/隐患/工单闭环和通知升级，以及按组织/设备统计处理效率；隐患分类的首期范围待确认。 |
| ALM-FR-008 | P0 | 技术事件与业务告警使用独立稳定 ID、状态和版本；转换关系记录策略版本、时间、执行服务和实际用户（如存在）。 |

## 12. ThingsBoard 优先候选集成边界（SPEC-TBI-01）

以下要求描述当前优先候选 ThingsBoard 的集成边界；如选型验证最终采用其他 IoT/时序组合，除 ThingsBoard 专有实体映射外，同等的业务标识、权限、审计和单一权威面约束仍然成立。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| TBI-FR-001 | P0 | 如采用 ThingsBoard，平台维护业务设备/结构/点位与其租户、客户、设备、资产或遥测键之间的显式映射。 |
| TBI-FR-002 | P0 | IoT 后端内部标识不得成为对用户展示的唯一业务标识。 |
| TBI-FR-003 | P0 | 如采用 ThingsBoard，平台可创建、同步、启停和查询所需 IoT 实体，但失败或部分成功须可重试、补偿和审计。 |
| TBI-FR-004 | P0 | ThingsBoard 或最终选定的 IoT 后端不作为人员、角色、物理结构模板、业务工单或 AI 权限的权威来源。 |
| TBI-FR-005 | P0 | 用户和 AI 查询 IoT 数据统一经过平台授权接口，不直接使用 IoT 后端管理凭据。 |
| TBI-FR-006 | P0 | 映射变更须防止历史数据串设备，并支持按生效时间解释。 |
| TBI-FR-007 | P1 | 平台应能检测共享控制面与最终 IoT 后端之间的实体或配置漂移，并提供可审计的修复建议/操作。 |
| TBI-FR-008 | P0 | 两个业务应用使用同一权威 IoT/时序访问面；数据采集处理应用可提供配置工作台，智能运维应用只消费授权数据，不各建一套设备/点位/遥测主库。 |
| TBI-FR-009 | P0 | Neuron 可作为边缘协议适配候选，但 ThingsBoard、EMQX、TDengine 等组件的权威边界须在架构设计中唯一确定，禁止未定义双写。 |
| TBI-FR-010 | P0 | 选型冻结前输出组件职责矩阵，逐项指定协议适配、消息传输、设备凭据、规范化、最新值、历史时序、波形对象、技术规则、查询 API 和保留策略的唯一写入者与权威查询入口。 |
| TBI-FR-011 | P0 | ThingsBoard、Neuron、EMQX、TDengine 等可以组成一套逻辑数据面，但任一事实只允许一个权威写入链和一个面向业务的受控查询契约。 |

## 13. 关键验收场景

- EQT-AC-001：模板含重复节点编码、缺少根节点或必需信息时不能发布。
- EQT-AC-002：发布新模板版本不会隐式改变基于旧版本创建的设备。
- EQT-AC-003：已发布版本不能原位编辑；用户只能从其派生新草稿并按草稿—审核—发布流程形成新版本，废止后已有实例仍可追溯。
- EQI-AC-001：设备由模板创建后包含必需节点，并能把检验图片关联到具体制动器。
- EQI-AC-002：升级模板遇到有点位绑定的待删除节点时，系统要求处理冲突而不直接删除。
- EQI-AC-003：数据应用创建的设备、结构和文件在运维应用以同一公共 ID 展示，不产生应用本地设备副本。
- CMP-AC-001：T 时刻更换减速机后结构路径和业务测点保持稳定；T 前后数据、文件和维修记录分别关联当时旧/新部件，历史不被重写。
- DAT-AC-001：套用接入模板后形成可检查配置；静态预检通过进入试运行，真实数据解析/映射/时间/质量验证通过后进入已启用，失败分类可定位。
- DAT-AC-002：一台 PLC 的不同点位可分别绑定起重机 A 的减速机和起重机 B 的制动器，查询不得串用。
- DQS-AC-001：无接入设备显示未接入/不适用，仍可进行结构、文件、巡检、工单和维修业务。
- DQS-AC-002：设备只有部分点位上报时显示部分接入和覆盖比例，诊断结论说明覆盖范围。
- DQS-AC-003：超过模板阈值后状态按规则进入延迟或中断；暂停后不再产生中断告警。
- TSDB-AC-001：重复同值保持幂等、重复异值形成冲突、迟到/乱序按窗口处理、人工修正不覆盖原值且聚合结果可解释。
- TSDB-AC-002：趋势查询同时返回值、单位、质量、测量/接收时间和数据来源。
- TSDB-AC-003：点位在 T 时刻从设备 A 改绑到 B 后，T 前后的历史分别按当时绑定和权限查询，不因当前绑定串用。
- WAV-AC-001：用户从异常振动特征或诊断结果可定位并按权限查看对应原始波形片段，普通趋势接口不返回全部高频样本。
- ALM-AC-001：同一规则事件转为业务告警后，技术恢复不会自动把正在人工处置的业务告警无审计关闭；两条时间线可相互追溯。
- TBI-AC-001：如采用 ThingsBoard，其同步部分失败时，平台显示一致性状态、失败原因并可安全重试；采用其他后端时执行等效集成验收。
- TBI-AC-002：用户或 AI 无法通过 ThingsBoard 或其他 IoT 后端标识绕过平台权限查询其他设备遥测。
- TBI-AC-003：同一测点在数据应用和运维应用返回相同值、时间、质量和绑定版本，任一候选组件都不能形成第二套未声明权威值。
- TBI-AC-004：架构选型输出的组件职责矩阵可逐项验证；任何组件故障或重试都不会绕过唯一写入者产生未定义双写。
