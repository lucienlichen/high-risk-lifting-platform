# 07 数据采集处理应用需求

## 1. 文档定位

本文件结合 /Users/lucien/Programs/Intelligent_data_agent_LE，定义它接入共享底座后的应用职责。该项目当前是前端原型，不是可直接复用的后端平台：

- 根目录 src 是功能较完整的 Vue/Pinia 原型，设备、文件、处理状态和登录主要保存在浏览器内存或 localStorage；
- v3 是另一套精简前端原型，虽然增加 API 适配、角色和系统设置概念，但仍以 mock 模式运行；
- RuoYi、EMQX/Neuron、TDengine、MinIO、RabbitMQ、OCR 和本地 LLM 均只出现在设计文档，仓库中没有对应生产后端服务；
- 原设计按单组织、org_id=1 预留字段，不满足本次已确认的简单多租户；
- 原 IoT 设计与 ThingsBoard 倾向存在双数据平面冲突，后续只选择一套权威接入/时序方案。

因此应复用其业务流程和页面意图，不把原设计文档的表结构或技术选型直接作为共享底座事实。

## 2. 应用目标

数据采集处理应用负责将设备相关的非结构化和结构化原始数据转化为可追溯、可复核、可供智能运维使用的数据产品：

~~~mermaid
flowchart LR
    S["文件 / 扫描件 / 表格 / API / IoT"] --> I["采集与归档"]
    I --> P["预处理 / 解析 / OCR"]
    P --> E["结构化 / 清洗 / 标准化"]
    E --> V["质量校验 / 人工复核"]
    V --> D["发布数据产品"]
    D --> M["智能运维监测 / 诊断 / 风险 / 维修"]
~~~

该应用不再拥有独立租户、用户、角色、组织、位置、设备主档或公共文件 ACL。上述能力全部来自共享底座。

## 3. 当前原型能力映射

| 原型能力 | 目标归属 | 说明 |
|---|---|---|
| 登录、人脸模拟、角色 | 共享底座 | 原型认证不进入生产 |
| 厂区/车间与设备列表 | 共享底座位置和设备 API | 目标版按 Location 建模；管理组织使用独立 Organization，不迁移原型本地数据 |
| 单台/批量设备建档 | 共享底座设备管理 | 数据应用可在授权下调用公共建档 API |
| 按设备×分类×日期上传 | 数据采集处理应用 + 共享文件服务 | 保留主要交互 |
| 历史文件导入、无数据标记 | 数据采集处理应用 | 保留并完善审计 |
| 图像预处理、OCR、结构化、清洗、聚类 | 数据处理服务 | 当前模拟变为异步任务 |
| 数据服务 AI 助手 | 数据应用助手 | 使用共享 AI 工具网关 |
| 隐患排查、问题处理、风险评估 | 智能运维应用 | 数据应用只提供输入数据和结构化结果 |
| 法规/前沿知识文档上传处理 | 共享文件/数据处理服务 | 知识发布、问答和业务应用由知识域/运维应用承担 |
| PLC/传感器接入配置 | 共享设备数据控制面 | 数据应用提供运维工作台，不自建第二套设备/点位 |

## 4. 数据分类与采集模板（SPEC-DCT-01）

原型已有的候选数据分类包括：

- 设备制造/出厂资料；
- 日常点巡检；
- 检验和检测；
- 故障和维修；
- 设备监管基础资料；
- 安全监控和健康监测；
- 风险相关输入；
- 法规、标准和技术知识文件。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DCT-FR-001 | P0 | 数据分类使用共享稳定编码和版本，定义名称、上级分类、适用设备类别、允许文件/数据类型和数据等级。 |
| DCT-FR-002 | P0 | 采集模板定义目标分类、业务日期规则、必需元数据、允许来源、文件限制、处理管线和结构化 Schema。 |
| DCT-FR-003 | P0 | 已发布采集模板不可原位覆盖，新版本不静默改变历史批次和已发布结果。 |
| DCT-FR-004 | P0 | 模板可声明数据应关联整机或某类物理结构节点；实例采集时绑定公共 equipmentId/structureNodeId。 |
| DCT-FR-005 | P0 | 数据分类、模板和 Schema 按租户可见范围授权；平台模板可被租户引用但不能由租户修改原版。 |
| DCT-FR-006 | P1 | 支持从已验证批次复制采集配置，并比较模板/Schema 版本差异。 |

## 5. 文件和批次采集（SPEC-ING-01）

### 5.1 采集来源

- 页面拖拽/选择文件；
- 批量历史文件；
- 受控 API 推送；
- 经批准的共享文件引用；
- IoT/边缘侧生成的事件文件或波形片段。

### 5.2 功能需求

| 编号 | 优先级 | 需求 |
|---|---:|---|
| ING-FR-001 | P0 | 用户选择公共设备、可选结构节点、数据分类和业务/归档日期后创建采集批次。 |
| ING-FR-002 | P0 | 支持图片、扫描 PDF、普通 PDF、Excel/CSV、Word 和经配置的其他格式；类型/大小白名单由租户策略控制。 |
| ING-FR-003 | P0 | 上传文件进入共享文件服务，批次保存文件资源 ID、明确文件版本及关联关系；重复文件按租户与 ACL 安全规则处理，不因内容相同形成跨租户可见性。 |
| ING-FR-004 | P0 | 每个批次记录 tenantId、applicationId、设备/节点、分类/模板版本、来源、创建用户、业务日期和状态。 |
| ING-FR-005 | P0 | 普通上传与历史导入分别记录用户选择日期、文件原始时间和最终业务日期，不把文件修改时间无条件视为业务事实。 |
| ING-FR-006 | P0 | 批量上传显示逐文件进度、校验结果、重复项和最终成功/失败清单；重复提交幂等。 |
| ING-FR-007 | P0 | “无数据”声明是受审计的业务记录，至少包含设备/节点、分类、日期、声明人、原因和撤销历史。 |
| ING-FR-008 | P0 | 删除采集关联不直接删除被其他对象引用的共享文件；原文件永久删除遵守保留与审批。 |
| ING-FR-009 | P0 | 采集批次可处于草稿、上传中、待处理、处理中、待复核、已发布、部分失败、失败、已取消状态。 |
| ING-FR-010 | P1 | 支持批次暂停、取消、重新处理和从失败步骤继续，并显示影响范围。 |

## 6. 处理管线与任务（SPEC-ETL-01）

### 6.1 可组合步骤

处理管线可按文件类型和 Schema 配置以下步骤，不要求每个文件全部执行：

1. 文件安全与完整性校验；
2. 图像去噪、矫正、增强和版面分析；
3. OCR 或原生 PDF 文本/表格抽取；
4. Excel/CSV/Word 解析；
5. 文档类型识别和 Schema 选择；
6. 字段结构化、单位/字典标准化；
7. 去重、异常值和一致性校验；
8. 可选聚类、统计和特征提取；
9. 人工复核；
10. 数据产品发布。

### 6.2 功能需求

| 编号 | 优先级 | 需求 |
|---|---:|---|
| ETL-FR-001 | P0 | 每个处理任务绑定租户、应用、采集批次、文件、管线版本、Schema 版本和发起用户。 |
| ETL-FR-002 | P0 | 任务状态至少包括待执行、执行中、等待复核、完成、失败、已取消；每个阶段和执行尝试独立记录。 |
| ETL-FR-003 | P0 | 任务幂等指纹至少覆盖 fileVersion/内容哈希、stage、pipelineVersion、SchemaVersion、模型版本和有效参数；同指纹重复消息不重复产物，任一影响结果的输入变化形成新执行版本。 |
| ETL-FR-004 | P0 | 失败记录失败阶段、类别、可重试性和脱敏错误信息；自动重试有上限，之后进入人工处理。 |
| ETL-FR-005 | P0 | 原文件、预处理产物、OCR 文本、结构化草稿和发布结果形成不可断裂的数据谱系。 |
| ETL-FR-006 | P0 | 每个提取字段记录值、原文/区域证据、置信度、标准化规则、模型/规则版本和修改来源。 |
| ETL-FR-007 | P0 | AI/LLM 生成的字段默认是草稿；低置信、冲突和敏感字段进入人工复核。 |
| ETL-FR-008 | P0 | 人工修正保留原值、修正值、用户、原因和时间，不覆盖处理证据。 |
| ETL-FR-009 | P0 | 处理任务执行前和发布前重新校验租户、设备/文件权限、对象版本和任务状态。 |
| ETL-FR-010 | P0 | OCR/模型不可用时不影响文件归档；任务保持明确待处理/失败状态，不伪造完成。 |
| ETL-FR-011 | P1 | 支持处理管线灰度版本、质量对比、回退和基于脱敏样本的回归评估。 |
| ETL-FR-012 | P1 | 支持并发/资源配额、优先级、队列进度和租户级用量统计。 |

## 7. Schema、结构化记录与质量（SPEC-DPR-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DPR-FR-001 | P0 | 结构化 Schema 定义字段编码、名称、类型、单位、字典、必填、校验、敏感等级和业务含义。 |
| DPR-FR-002 | P0 | Schema 与数据分类、设备类别和文档类型关联，并采用草稿、审核、已发布、已废止版本生命周期。 |
| DPR-FR-003 | P0 | 结构化记录至少引用 tenantId、equipmentId、可选 structureNodeId/componentAssetId、sourceFileId/sourceFileVersion、batchId、Schema/管线版本和业务日期。 |
| DPR-FR-004 | P0 | 系统计算完整率、字段置信度、校验错误和复核状态，不能只给笼统“AI 准确率”。 |
| DPR-FR-005 | P0 | 发布前执行必填、类型、单位、引用、重复和跨字段规则；失败不能进入正式数据产品。 |
| DPR-FR-006 | P0 | 已发布结果不可静默覆盖，修改形成新版本并说明替代关系。 |
| DPR-FR-007 | P0 | 同一原文件可产生多个不同用途的数据产品，但用途、Schema 和发布状态必须明确。 |
| DPR-FR-008 | P1 | 支持同类文档批次质量统计、模板漂移和异常分布分析。 |

## 8. 数据产品发布与消费（SPEC-DPD-01）

“数据产品”指经过明确 Schema、质量校验和权限控制，可被其他服务稳定查询的发布结果。

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DPD-FR-001 | P0 | 数据产品定义产品编码、版本、Schema、业务所有者、数据等级、可用 API/事件和质量门槛。 |
| DPD-FR-002 | P0 | 发布操作记录复核人、发布时间、来源谱系、质量摘要和适用范围。 |
| DPD-FR-003 | P0 | 智能运维应用按公共设备/结构 ID、分类、时间和版本查询，不直接读取 ETL 内部任务表。 |
| DPD-FR-004 | P0 | 消费 API 返回来源文件、业务日期、发布时间、质量、版本和数据新鲜度。 |
| DPD-FR-005 | P0 | 数据产品撤回/废止不删除已被历史运维结论引用的版本；新的业务计算不得默认使用废止版本。 |
| DPD-FR-006 | P0 | 发布、替代、撤回通过可靠事件通知订阅应用；消费者按 eventId 和产品版本幂等处理。 |
| DPD-FR-007 | P0 | 权限变化、设备归属变化或文件密级变化时，消费查询和缓存按最新 ACL 重新校验。 |
| DPD-FR-008 | P1 | 支持字段级订阅、批量导出和经审批的外部接口。 |
| DPD-FR-009 | P0 | 区分数据产品定义、不可变发布版本和记录修订；已发布版本不能原位覆盖，修正通过新修订/版本和替代关系表达。 |
| DPD-FR-010 | P0 | 运维结论保存精确 evidenceRef，至少包含产品发布版本/记录修订；引用时序证据时同时包含时间窗、测点绑定版本和算法/规则版本。 |

## 9. IoT 采集工作台边界（SPEC-DIW-01）

数据应用可提供数据源、接入模板、点位和运行质量的配置工作台，但底层身份和遥测服务必须与 02/06 文档一致：

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DIW-FR-001 | P0 | 工作台使用共享数据源、点位和结构绑定，不维护另一套 device/metric 表。 |
| DIW-FR-002 | P0 | 配置和查看 Modbus、OPC-UA、MQTT 或其他适配能力时，通过统一 IoT 服务执行。 |
| DIW-FR-003 | P0 | 智能运维应用与数据应用查询同一最新值、时序和质量状态，不进行双写同步。 |
| DIW-FR-004 | P0 | ThingsBoard 与 EMQX/Neuron/TDengine 等候选方案在架构选型阶段统一，不能让两个应用分别成为权威数据源。 |
| DIW-FR-005 | P0 | IoT 接入故障不影响文件采集/ETL，文件处理故障也不改变设备实时接入状态。 |

## 10. 数据处理 AI 助手（SPEC-DPAI-01）

| 编号 | 优先级 | 需求 |
|---|---:|---|
| DPAI-FR-001 | P0 | 所有有效用户可进入共享 AI 助手，但只有获 data-processing 应用和相应工具权限者能操作采集/处理任务。 |
| DPAI-FR-002 | P0 | 可帮助选择设备、结构、分类、模板和 Schema，解释处理失败，生成字段草稿和复核建议。 |
| DPAI-FR-003 | P0 | AI 不直接修改原文件或已发布结果；重新处理、修正和发布均通过版本化 API、确定性确认和审计。 |
| DPAI-FR-004 | P0 | AI 查询处理结果时返回文件/批次、管线/Schema/模型版本、质量和发布状态。 |
| DPAI-FR-005 | P0 | AI 日志同时关联 tenantId、applicationId、实际用户、设备、文件、任务、字段和最终数据产品。 |
| DPAI-FR-006 | P1 | 支持自然语言创建采集/处理任务草稿和批量复核队列，正式执行受额度和风险策略限制。 |

## 11. 与智能运维应用的边界

以下能力从数据应用中移出或不再重复实现：

- 设备风险评分、隐患排查、问题工单和维修闭环由智能运维应用负责；
- 健康/安全监测业务页面由智能运维应用负责，数据应用只提供接入、时序和质量工作台；
- 法规/标准文件的采集、OCR 和索引构建可由数据处理服务完成，知识发布和问答使用统一知识/AI 服务；
- 设备、人员和权限管理只在共享管理控制台提供。

数据应用可以展示数据质量和处理技术指标，但不得将处理完成状态等同于设备健康、风险或安全结论。

## 12. 关键验收

- ING-AC-001：租户 A 用户只能为本租户授权设备创建批次，篡改 tenantId、equipmentId 或 fileId 被拒绝。
- ING-AC-002：用户上传检验扫描件后原文件只保存一次，批次、文件、设备和结构节点关系可追溯。
- ING-AC-003：历史导入同时保存文件原时间和用户确认的业务日期；系统不把修改时间直接当检验日期。
- ING-AC-004：“无数据”声明可撤销且保留实际用户、原因和历史。
- ETL-AC-001：扫描件经过预处理、OCR、结构化和复核后发布，任一字段可定位原文证据和处理版本。
- ETL-AC-002：重复任务消息不重复生成结果；失败重试用尽后进入人工队列且不丢原文件。
- ETL-AC-003：AI 提取低置信字段未经用户复核不能发布为正式数据。
- DPR-AC-001：人工修正不覆盖 AI 原值，发布新版本后旧版本仍能解释历史运维结论。
- DPD-AC-001：运维应用用公共设备 ID 查询发布结果，获得来源、不可变发布版本、记录修订、质量和复核信息而不能访问 ETL 私有状态。
- DPD-AC-002：撤回某数据产品后新评估不再默认使用，历史已引用结论仍可追溯原版本。
- DIW-AC-001：同一测点在两个应用显示相同值、时间和质量，不存在两套连接状态。
- DPAI-AC-001：数据处理助手发起重新处理时，审计可反查实际用户、应用、文件、任务、确认和最终版本。
